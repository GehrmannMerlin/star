# crawler-test-regressions Skill 设计规格

日期：2026-08-02  
状态：书面规格待用户审阅  
适用范围：第 13 个独立 Agent Skill `crawler-test-regressions` 的完整设计

## 1. 目标与边界

`crawler-test-regressions` 是爬虫知识资料库平台保障方向下的 Agent 爬虫测试与修复验证顾问。其职责是：依托固定版本资料、测试指南、故障案例和合规源码，并结合已经确认的根因与项目验收标准，帮助 Agent 设计单元测试、集成测试、回放测试、契约测试、金标数据、故障注入、性能和安全回归。修复前，负责形成能够稳定暴露问题的失败案例；用户批准实施后，指导或协助 Agent 运行相关测试并保存结果证据。

本 Skill **不是**项目测试体系的替代品。它检查修复是否真正解决原问题、是否引入新问题，以及外部网站异常是否被错误计入项目自身测试失败。安全或正确性硬门槛失败时必须阻止通过。

本设计只规划 `crawler-test-regressions`，不包含第 14 个及后续 Skill 的实施任务；不创建或实施本 Skill 本身（实施由 Claude Code 按后续写作计划执行）。

## 3. 职责与排除项

### 3.1 职责

- 设计测试以验证修复有效性与防止回归：
  - 单元测试、集成测试、回放测试、契约测试；
  - 金标数据、故障注入、性能和安全回归。
- 修复前，形成能够稳定暴露问题的失败案例。
- 用户批准实施后，指导或协助 Agent 运行相关测试并保存结果证据。
- 检查修复是否真正解决原问题、是否引入新问题，以及外部网站异常是否被错误计入项目自身测试失败。
- 输出测试范围、测试依据、通过或失败结果、未覆盖风险和发布阻断结论。
- 安全或正确性硬门槛失败时，必须阻止通过（发布阻断）。

### 3.2 排除项

- 不替代领域 Skill 诊断根因；测试发现新的未知问题时，必须退回 `crawler-triage-incidents`（主决策日志 §58）。
- 无结果证据时不得宣称修复成功。
- 关键回归失败时不得放行。
- 不把外部网站异常错误计入项目自身测试失败。
- toxiproxy 按主决策日志 §70 边界：只作为受控网络退化案例的知识来源，不授权启动代理、影响现有环境或注入故障。
- 不攻击外部网站、不绕过访问控制、不把未经审查的第三方示例代码用于项目。
- 不生成 `writing-plans`、不提出未经批准的代码修改。
- 不修改爬虫代码、`manifest.md`、第三方仓库；不初始化 Git。
- 不把密钥、Cookie、认证请求头、代理凭据、环境变量中的秘密写入诊断记录，落盘前脱敏。

## 4. 触发条件与输入

### 4.1 触发

用户要求检查测试与修复验证相关设计或故障，或已经确认的问题需要形成回归测试、验证修复有效性、设计测试体系、判定发布阻断时触发（主决策日志 §58）。通常由 `crawler-triage-incidents` 分诊路由进入（已确认根因后），或用户直接要求测试设计/回归验证。

### 4.2 最低输入

- 项目上下文（处理 Stellaris 问题时为 `stellaris-crawler-context` 项目上下文包路径）。
- 已确认根因与方向（`crawler-triage-incidents` 分诊结论，适用时）。
- 相关代码、测试体系、依赖版本、验收标准、复现证据。
- 固定版本资料（批次 3/4：pact-specification、JSON-Schema-Test-Suite、toxiproxy、locust、in-toto）。

## 5. 诊断流程

1. 读取项目上下文（Stellaris 问题先读 `stellaris-crawler-context` 项目上下文包）、目标、约束与已确认根因。
2. 确定诊断聚焦点：单元/集成测试设计 / 回放测试与金标数据 / 契约测试 / 故障注入与性能测试 / 安全回归 / 修复验证与发布阻断。
3. 检查相关代码、测试体系、依赖版本、验收标准、复现证据，定位具体证据位置。
4. 引用匹配版本的证据卡（`test-regressions.md`）比对项目行为与规范/实现/工程证据。
5. 修复前：设计能够**稳定暴露问题**的失败案例（RED）；用户批准实施后指导运行并保存结果证据（GREEN）。
6. 检查修复是否真正解决原问题、是否引入新问题、外部网站异常是否被错误计入项目自身测试失败。
7. 测试发现新的未知问题时，必须退回 `crawler-triage-incidents`。
8. 输出测试范围、测试依据、通过或失败结果、未覆盖风险和发布阻断结论。
9. 安全或正确性硬门槛失败时，必须阻止通过（发布阻断）；获准的修复方向交给 `crawler-writing-plans-bridge`。

## 6. 测试设计规则

- 先写能稳定暴露问题的失败案例，再写修复（RED-GREEN 纪律）。
- 测试必须可复现、有结果证据；无结果证据时不得宣称修复成功。
- 外部网站异常与项目自身缺陷必须分离，不得把外部条件误计入项目测试失败。
- 金标数据与回放测试基于已保存证据，不依赖实时抓取。
- 每条结论必须明确区分：事实、证据、综合推断、待确认项。综合推断必须显式标记为"推断"，不得伪装成资料中的确定结论（主决策日志 §14）。
- 置信度使用固定枚举：高（证据充分且指向唯一分类）、中（证据充分但多个分类可能）、低（证据不足或冲突，仅候选假设）、不确定（无法判断）。

## 7. 证据卡主题分组

共享证据卡 `docs/superpowers/knowledge/evidence-cards/test-regressions.md` 从批次 3/4 固定资料筛选，按以下主题分组（实施时按实际固定资料筛选具体卡片）：

1. **单元/集成测试与断言**：JSON-Schema-Test-Suite `tests/`（draft3-draft2020-12 各草案版本校验语义，作断言/金标基础）。
2. **回放测试与金标数据**：JSON-Schema-Test-Suite `tests/`、`output-tests/`（金标比对）；in-toto 验证流程。
3. **契约测试**：pact-specification `implementation-guidelines/`（契约测试语义）。
4. **故障注入与性能测试**：toxiproxy `toxics/`、`link.go`（网络退化模拟——按主决策日志 §70 只作受控案例知识）；locust 负载测试源码。
5. **安全回归与发布阻断**：in-toto 验证流程（安全回归复核）；安全修复回归判定。

## 8. 输出契约

诊断记录采用可落盘结构化记录＋简短人类可读摘要（主决策日志 §33 节），每条结论可追溯。固定字段：

- 测试范围（覆盖的模块/功能/接口/回归面）。
- 测试依据（已确认根因、验收标准、固定版本资料、证据卡引用）。
- 通过/失败结果（可复现的测试运行证据，区分项目缺陷与外部条件）。
- 未覆盖风险（测试盲区、无法验证的部分）。
- 发布阻断结论（通过 / 需修复 / 阻止发布；安全或正确性硬门槛失败时明确阻止）。
- 测试设计与运行证据（失败案例、运行结果、结果证据位置）。
- 交接对象（新未知问题→`crawler-triage-incidents`；获准修复方向→`crawler-writing-plans-bridge`）。

记录必须明确区分：事实、证据、推断、待确认项与用户批准状态。

## 9. 交接契约

- 遵守主决策日志第 33-36 节：可落盘结构化记录＋简短人类摘要；双层存储（小型记录项目内保存、大型证据以内容哈希和相对路径引用）；敏感信息落盘前脱敏。
- 测试发现新的未知问题时，必须退回 `crawler-triage-incidents`，不自行下钻领域根因。
- 无结果证据时不得宣称修复成功；关键回归失败时不得放行（发布阻断）。
- 获准的修复方向交给 `crawler-writing-plans-bridge` 作为规划输入，不取代其规划职责。
- 诊断结论明确区分事实、证据、推断、待确认项与用户批准状态。

## 11. 验证设计

### 11.1 结构验证

静态检查：
- Skill 包文件齐全（SKILL.md、test-workflow.md、output-contract.md）。
- 共享证据卡 `test-regressions.md` 与知识视图 `crawler-test-regressions.md` 存在；知识视图引用证据卡。
- 诊断流程与测试设计规则、发布阻断判定在 references 中明确定义。
- 无 `TBD`、`TODO`、`FIXME` 占位符。
- 无肯定式运行指令；仅有负面安全声明与诊断流程描述。
- 不含敏感信息示例（密钥、Cookie、认证头、代理凭据）。
- 非 Git 边界：项目根目录不是 Git worktree；不初始化 Git。

### 11.2 行为验证（RED/GREEN）

按 `superpowers:writing-skills` 方法运行固定行为案例，每个案例使用全新隔离的 Agent 上下文：

- 按诊断聚焦点聚焦：只诊断触发问题对应的聚焦点，不无边界扩展。
- 形成失败案例：修复前能形成稳定暴露问题的失败案例。
- 回归验证：检查修复是否真正解决原问题、是否引入新问题。
- 外部条件分离：不把外部网站异常错误计入项目自身测试失败。
- 无结果证据不宣称修复成功：无测试运行证据时不宣称成功。
- 发布阻断：安全或正确性硬门槛失败时阻止通过。
- 新未知问题退回分诊：测试发现新的未知问题时退回 `crawler-triage-incidents`。
- 敏感信息脱敏：诊断记录不含密钥/Cookie/认证头/代理凭据/环境变量中的秘密。

### 11.3 验收标准（对应主决策日志 §58）

- 固定缺陷能够被测试捕获。
- 无结果证据时不能宣称修复成功。
- 关键回归失败时能够正确阻止通过。

达到上述标准即视为本 Skill 当前细节设计充分，不再扩展低优先级内部设计。

## 12. 阶段门

本规格经用户审阅批准后，才可调用 `superpowers:writing-plans` 生成 `crawler-test-regressions` 的单 Skill 实施计划。用户未明确批准前，不进入 `writing-plans`，不实施本 Skill，不开始第 14 个 Skill。

`E:\Stellaris` 当前不是 Git 仓库。本设计只要求把文档可靠保存在本地项目中，不得为了满足提交步骤擅自初始化 Git。
