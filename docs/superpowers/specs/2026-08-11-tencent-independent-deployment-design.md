# Stellaris 腾讯云独立部署与账号隔离设计

## 1. 背景

当前公开入口 `https://tongjixinzhi.cn/zhengwujianli/` 位于腾讯云服务器 `43.142.31.198`，但只在腾讯云托管子路径前端，`/zhengwujianli/api/` 仍反向代理到阿里云 `https://stellaris.ac.cn/api/`。因此，腾讯云入口与阿里云 Stellaris 后端、PostgreSQL、证据文件及导出文件仍然耦合。

腾讯云 Homer 应用中心使用 `/www/wwwroot/auth-system` 提供共用员工账号。现有登录状态主要保存在同域浏览器 `localStorage` 的 `auth_user` 和 `employeeAuthUser` 中，尚无可供 Stellaris 后端信任的服务端会话。仅依赖浏览器用户信息无法安全实现任务按账号隔离。

本设计将本地 `E:\Stellaris` 复制为腾讯云专用版本，独立部署完整前端、后端和数据库，并在不改变其他项目既有登录接口行为的前提下增加 Stellaris 专用服务端会话。

## 2. 已确认决策

- “新分支”指本地独立项目副本，不是 Git 分支。
- 本地专用副本目标路径为 `E:\Stellaris-Tencent`。
- 腾讯云部署使用全新空数据库，不迁移阿里云任务、证据或导出数据。
- 已登录控制台的用户进入项目时不进行第二次登录。
- 未登录用户直接访问项目时返回控制台登录，登录成功后返回原项目路径。
- 每个账号严格只能访问自己的任务；管理员也没有跨账号查看或管理权限。
- 腾讯云入口切换后不再向 `stellaris.ac.cn` 反代任何 Stellaris 页面或 API。
- 阿里云原项目和 `https://stellaris.ac.cn/` 保持独立运行，不删除其服务或数据。
- Homer 现有“政务简历采集”卡片、封面、排序和链接保持不变。

## 3. 目标与非目标

### 3.1 目标

1. 在腾讯云运行独立的 Stellaris Web、Backend 和 PostgreSQL。
2. 让 `/zhengwujianli/` 页面、静态资源、API、SSE 和导出全部由腾讯云本机服务提供。
3. 复用腾讯云共用员工账号，实现无二次登录的安全访问。
4. 在服务端强制执行任务所有权，防止通过伪造用户 ID 或猜测任务 ID 越权。
5. 使用可验证、可回滚的方式切换流量。

### 3.2 非目标

- 不迁移阿里云业务数据。
- 不停止或删除阿里云 Stellaris。
- 不重构其他腾讯云项目的账号逻辑。
- 不为管理员增加跨账号权限。
- 不重新发布或重新生成 Homer 卡片封面。
- 不在本次工作中修订共用账号系统的员工数据、密码规则或其他历史安全问题。

## 4. 部署架构

### 4.1 本地副本

创建 `E:\Stellaris-Tencent` 作为独立源码副本。复制源码、配置、测试和锁文件，但不复制 `node_modules`、构建产物、临时归档以及运行数据。腾讯云专属认证与部署改动只进入该副本，后续用户系统修改也在该副本维护。

当前 `E:\Stellaris` 不含 `.git`，因此不能创建或提交 Git 分支。副本必须保留一份来源说明和首次复制清单，以便追溯基线。

### 4.2 腾讯云运行目录

腾讯云使用独立目录 `/opt/stellaris-zhengwujianli`，包含部署清单、只读应用配置和持久化数据目录。服务至少包括：

- Web：提供带 `/zhengwujianli/` 基础路径的前端构建。
- Backend：提供任务、结果、证据、事件流、控制和导出 API。
- PostgreSQL：使用全新专用数据目录。

容器名、Compose 项目名、端口、Docker 网络和持久化路径不得与现有腾讯云项目冲突。Web 与 Backend 不直接暴露公网端口；需要宿主机端口时只绑定 `127.0.0.1`。数据库不暴露公网。

### 4.3 容量边界

服务器盘点时根卷约 1000 GB、可用约 676 GB；内存约 7.5 GiB、可用约 3.2 GiB，且已有较高 Swap 使用。部署需为数据库、后端和浏览器型爬虫设置合理的资源约束，并在切流前用真实小任务验证不会使现有项目出现明显资源争用。

### 4.4 浏览器运行时快速部署

腾讯云到 Playwright 官方 Chromium CDN 的持续吞吐过低，因此不再把 Playwright 固定版本浏览器下载作为镜像构建步骤。Backend 镜像改为从已验证的腾讯 Debian 镜像安装系统 `chromium`，并通过环境变量 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium` 传入爬虫浏览器启动层。未设置该变量时仍保留 Playwright 默认行为，便于本地开发继续使用 Playwright 管理的浏览器。

切换只修改生产浏览器启动边界和镜像依赖，不改变抓取业务逻辑。部署验证仅运行一次容器内 Chromium 启动/退出冒烟并确认版本输出，不再下载 Headless Shell，也不运行全量爬虫测试。此前生成的官方浏览器临时文件保留用于审计，不删除、不进入正式镜像。

## 5. 共用账号的兼容扩展

### 5.1 现有行为保持不变

现有 `/auth/api/verify-login` 的请求字段、HTTP 成功条件和 JSON 返回结构保持兼容。其他项目继续使用原有 `localStorage` 登录状态，不要求迁移到新会话。

### 5.2 Stellaris 专用会话

员工账号密码验证成功时，账号服务额外签发一个 Stellaris 专用的签名会话 Cookie。Cookie 必须：

- 使用唯一名称，避免与其他项目冲突；
- 设置 `HttpOnly`、`Secure` 和合适的 `SameSite`；
- 将路径限制为 `/zhengwujianli/`；
- 初始有效期为 24 小时；
- 不包含密码、身份证号或其他敏感字段；
- 使用服务器端独立密钥签名。

签名密钥存放在权限为 `600` 的服务器本地配置文件或受控环境变量中，不进入源码、镜像、日志或浏览器可读状态。

账号服务新增专用会话校验和清除能力。校验时除验证签名与有效期外，还需重新查询员工数据库，确认用户仍存在且账号未过期。账号删除或实习期过期后应立即拒绝，不等待 Cookie 自然到期。

### 5.3 登录、返回与退出

- 有效会话：用户直接进入 `/zhengwujianli/`。
- 缺少或无效会话：跳回控制台登录，并携带经过白名单校验的站内返回路径。
- 登录成功：返回 `/zhengwujianli/` 或原站内子路径。
- 控制台退出：除清除既有 `localStorage` 外，同时清除 Stellaris 专用 Cookie。
- 升级前已登录但没有新 Cookie 的用户：首次进入项目时需要重新登录一次。

返回路径只允许同源、以 `/zhengwujianli/` 开头的相对路径，防止开放重定向。

### 5.4 对其他项目的影响控制

- 不替换现有认证路由。
- 不修改员工表结构和员工数据。
- 不要求其他项目读取或验证新 Cookie。
- Cookie 路径限定后，浏览器不会把它发送给其他应用路径。
- 账号服务修改前创建可恢复备份，并先在备用端口进行登录回归。
- 正式重启只产生短暂登录接口窗口；已打开的其他项目不应被强制退出。

## 6. Nginx 认证边界

Nginx 是公网请求进入腾讯云 Stellaris 的唯一入口。对 `/zhengwujianli/` 和 `/zhengwujianli/api/` 进行会话校验，并只在校验成功后代理到本机服务。

账号服务的内部校验响应向 Nginx返回可信用户 ID。Nginx 覆盖并注入内部身份头后再转发给 Backend，必须丢弃客户端提交的同名身份头。Backend 只接受来自受控本机或专用网络的代理请求，不允许公网绕过 Nginx。

认证失败行为：

- 页面请求：跳转控制台登录。
- API、SSE 和导出请求：返回 `401`，由前端触发重新登录。
- 账号服务不可用：返回 `503`，不得降级为匿名访问。

## 7. 任务所有权模型

### 7.1 数据模型

全新数据库从首次迁移起为任务保存不可为空的 `owner_user_id`。可额外保存创建时的用户显示名作为审计快照，但授权决策只使用稳定用户 ID。

因为腾讯云数据库为空，不需要为历史任务推断所有者，也不允许产生无所有者任务。

### 7.2 创建任务

创建任务时，Backend 从 Nginx 注入的可信身份取得 `owner_user_id`。请求体中的任何用户 ID 字段均不参与授权，也不能覆盖所有者。

### 7.3 强制隔离范围

以下操作都必须在数据库或仓储查询层同时匹配任务 ID 和当前 `owner_user_id`：

- 任务列表和任务详情；
- 结果、领导结构和恢复结果；
- 证据、日志和运行状态；
- SSE 事件流；
- 暂停、继续、取消、重试及其他任务控制；
- Excel 或其他导出；
- 与任务关联的文件下载。

访问其他账号的任务统一返回 `404`，避免泄露任务是否存在。所有账号包括管理员均遵循相同限制。

### 7.4 Worker 边界

异步 Worker 可按任务 ID 执行后台工作，但不决定面向用户的权限。所有浏览器可调用的读取、控制和下载接口都必须重新校验任务所有者。

## 8. 前端行为

前端使用 `/zhengwujianli/` 基础路径构建，并统一生成同前缀 API URL。前端可以展示当前账号名称，但不得依赖浏览器用户对象进行授权。

收到 `401` 时，前端停止继续请求并进入重新登录流程。收到 `404` 时按“任务不存在或无权访问”处理。账号服务或 Backend 返回 `503` 时显示服务暂不可用，不清空用户本地界面状态。

## 9. 腾讯云路径切换

当前 Nginx 中：

- `/zhengwujianli/` 从腾讯云静态目录提供；
- `/zhengwujianli/api/` 代理到 `https://stellaris.ac.cn/api/`。

目标状态为页面和 API 均指向腾讯云独立服务。正式配置中该路径范围不得再出现 `stellaris.ac.cn` 上游。Homer `APP_DATA` 中已有卡片继续使用 `/zhengwujianli/`，`DEFAULT_ORDER` 和卡片封面不变。

阿里云 `https://stellaris.ac.cn/` 继续独立提供原系统，不因腾讯云切流而停止。

## 10. 发布顺序与回滚

### 10.1 发布顺序

1. 记录当前公网页面、API 和阿里云站点基线。
2. 备份账号服务、Homer 首页、Nginx 活动配置和现有子路径静态目录。
3. 创建本地独立副本并完成认证、所有权、部署配置及测试。
4. 在腾讯云独立目录上传候选版本并启动专用容器，暂不接管公网路径。
5. 通过本机临时入口验证数据库为空、服务健康、账号会话和双账号任务隔离。
6. 在备用端口验证账号服务修改，确认原登录响应兼容后再受控重启 PM2。
7. 生成候选 Nginx 配置，确认标记块唯一并运行 `nginx -t`。
8. 仅在语法检查通过后原子替换活动配置并 reload。
9. 执行公网验收；全部通过后保留备份和阿里云独立站。

### 10.2 回滚触发条件

以下任一情况触发回滚：

- 控制台登录或其他代表性项目登录回归失败；
- 未登录访问未被阻止；
- 两个账号之间出现任何任务越权；
- 页面、静态资源、API、SSE 或导出关键验收失败；
- 腾讯云资源争用明显影响既有项目；
- `nginx -t` 或服务健康检查失败。

### 10.3 回滚动作

恢复账号服务文件和进程、Nginx 活动配置及原子路径备份；运行 `nginx -t`，仅在通过后 reload。回滚后 `/zhengwujianli/api/` 重新指向当前阿里云版本，并再次验证 Homer 首页和阿里云站点。

腾讯云新数据库为独立空库，回滚不需要反向同步到阿里云。

## 11. 测试与验收

### 11.1 本地自动化验证

采用用户批准的快速交付模式，不再在每个任务后重复运行全仓或全包测试。已取得的成功结果直接复用；后续每项改动仅运行与该改动直接相关的局部测试，以及受影响包的一次类型检查。候选版本打包前只运行一次前后端生产构建。

不得省略的本地关键验证仅包括：可信身份缺失时拒绝访问、双账号任务所有权、会话签名与过期、`/zhengwujianli/` 基础路径，以及最终生产构建。其他全量回归测试不作为继续部署的前置条件。

### 11.2 双账号隔离测试

使用两个受控测试账号 A 与 B：

1. A 创建任务 A1，B 创建任务 B1。
2. A 的列表只包含 A1，B 的列表只包含 B1。
3. A 访问或控制 B1 的详情、结果、证据、SSE、导出和控制接口均得到 `404`。
4. B 对 A1 执行相同测试，结果一致。
5. 管理员测试账号也只能访问自己创建的任务。

测试不得读取或输出真实员工密码、身份证号或其他敏感数据。

### 11.3 公网验收

- Homer 首页和现有代表性应用保持正常。
- 卡片仍指向 `/zhengwujianli/`。
- 未登录访问跳转登录，登录后正确返回。
- 退出登录后项目会话立即失效。
- HTML、JS、CSS、API、SSE 和导出均由腾讯云路径提供。
- 腾讯云数据库首次启动为空。
- 双账号隔离测试全部通过。
- Nginx 的 Stellaris 路由不再引用 `stellaris.ac.cn`。
- `https://stellaris.ac.cn/` 原站仍返回正常响应。

## 12. 完成标准

只有在上述最小关键验证、腾讯云临时入口验证、账号兼容回归、双账号隔离和公网验收通过后，迁移才算完成。任何关键检查未通过时必须回滚，不得以客户端隐藏、仅前端过滤或手工约定代替服务端权限控制。逐任务全量测试、重复构建和重复代码审查均不再作为完成条件。
