# 政务简历采集前端 UI 重构设计

> 设计日期：2026-08-11
>
> 设计状态：用户已确认
>
> 视觉基准：用户上传的任务台与历史记录最终 UI 参考图

## 1. 目标

在完全保留现有业务逻辑、数据流、接口、事件、状态管理和页面功能的前提下，对“任务台 / 政务简历采集配置”和“历史记录 / 任务记录”两个现有页面进行纯 UI 重构。最终页面使用清新、明亮、轻量、专业的政务工具视觉语言，并尽可能高精度复刻参考图。

本次工作遵循“换皮，不换骨架”：只调整 CSS、视觉资源和必要的布局包装，不重写业务组件，不添加新业务功能，不制造演示数据。

## 2. 当前实现

- 前端技术栈：React 19、TypeScript 6、Vite 8、原生 CSS。
- 任务台入口：`apps/web/src/components/TaskForm.tsx`。
- 行政区范围组件：`apps/web/src/components/RegionPicker.tsx`。
- 历史记录入口：`apps/web/src/components/TaskHistory.tsx`。
- 共享 Header、页面状态导航和任务详情：`apps/web/src/app.tsx`。
- 全局及页面样式：`apps/web/src/app.css`。
- API 生产实现：`apps/web/src/main.tsx`。
- 页面切换由 `App` 内部 `view` 状态实现，没有引入路由库。
- 历史表格数据来自真实 `api.listTasks()` 返回值，并通过 `tasks.map()` 渲染。

## 3. 业务冻结清单

以下内容不得修改语义或行为：

- `ApiClient` 接口和 `main.tsx` 内所有 API URL、请求方式、参数及响应解析。
- `WorkspaceView.handleSubmit`、`buildCreateRequest`、任务创建与结果加载流程。
- `TaskForm` 的表单状态、提交处理、字段值、`required`、radio 选中条件和 `disabled` 表达式。
- `FULL_INSTITUTION`、`TARGETED`、`COUNTY`、`TOWN_STREET` 等业务枚举。
- `RegionPicker` 的省份加载、地市加载、多选、名单校验、层级展开、错误提示和 `onChange`。
- Header 的 `navigate` 调用和工作台、历史记录、详情回看之间的视图切换。
- `TaskHistory` 的 `load`、状态筛选、模式筛选、分页、错误态、加载态、空态、行点击和真实数据源。
- 任务暂停、继续、取消、结果表、证据抽屉和导出行为。

现有历史分页虽然没有出现在参考截图中，但属于现有功能，必须保留。它只会被设计成低强调控件，不会删除或改变行为。

## 4. 改造方案

采用 CSS 优先的最小 DOM 调整方案：

1. 用 CSS Custom Properties 建立只服务于当前 Web 应用的颜色、圆角、阴影和间距 Token。
2. 替换现有页面级布局样式，使应用铺满视口，并提供共享 Header 和背景装饰。
3. 仅在现有 JSX 中增加布局 wrapper、图标装饰节点和必要的页面修饰 class。
4. 保留所有原生 `form`、`select`、`textarea`、`input`、`button`、`table` 语义及绑定。
5. 使用本地 SVG 作为 CSS mask，不安装图标组件库，也不产生运行时远程请求。

不采用组件整体重写，也不为了本次换肤拆分新的状态层、路由层或数据组件。

## 5. 共享视觉层

### 5.1 页面背景

- 页面使用接近 `#F8FBFA` 的暖青白背景。
- 左上和右下的薄荷绿色抽象曲线由 `.app-main` 伪元素和低透明度渐变实现。
- 背景装饰不创建业务 DOM，不响应指针事件，不遮挡页面内容。

### 5.2 颜色与文字

- 主色：`#159C91`。
- Hover：`#128A81`。
- 浅色主色背景：`#EAF8F6` / `#F1F9F7`。
- 主文字：`#172321`。
- 正文：`#263533`。
- 辅助文字：`#7E8A88`。
- 边框：`#DDE8E6`。

字体继续使用系统字体栈，不引入网络字体。

### 5.3 Header

- Header 高度约 84px，白色背景，带极轻阴影。
- 内容横向铺开，左侧为本地品牌图标、产品名和“本机运行”，右侧保留任务台、历史记录两个按钮。
- Active 按钮为 teal 背景和白色文字；普通按钮为白底、浅边框和深色文字。
- 既有 `onClick` 和 `view.name` active 判断保持不变。

## 6. 任务台设计

- 表单容器位于页面偏左中部，桌面端核心宽度约 640px，并保留大面积留白。
- 模式 radio 位于主 Card 上方，使用统一 teal 激活样式。
- 完整机构模式继续渲染原 `RegionPicker`；其 fieldset 被视觉化为白色 Card，圆角约 12px，浅边框和柔和阴影。
- “采集范围”标题保留 fieldset/legend 语义，使用左侧 teal 竖线装饰。
- 两个现有 select 横向排列并自然收缩；`multiple` 属性和所有选项数据保持不变。
- textarea 高约 104px，保持现有 value、onChange、placeholder 和校验逻辑。
- “校验并添加”为 teal outline 次按钮。
- 展开层级区域使用浅分隔线，radio 与顶部模式选择保持一致。
- “开始采集”位于 Card 下方居中，保持 submit 类型及原 disabled 条件，并添加本地 `circle-play` 图标。
- 指定机构模式中现有四个字段全部保留，放入与采集范围一致的 Card 视觉中，不删除任何字段。
- 任务创建后出现的任务状态、控制按钮、结果表和证据抽屉继续正常渲染，并使用相同视觉 Token 做兼容样式。

## 7. 历史记录设计

- 历史内容区域桌面端最大宽度约 1320px，居中显示。
- “任务记录”标题使用 20–22px 深色半粗体。
- 两个现有筛选 select 横向排列，宽约 160px，高约 46px。
- 真实数据表放入白色大 Card，外层增加横向滚动 wrapper 以适应窄窗口。
- 表头使用极浅 mint 背景、约 44px 高度和中等字重。
- 行高约 50px，使用浅分隔线；hover 为极浅 teal。
- 列名、字段含义、`tasks.map()`、行点击详情和时间格式化保持不变。
- 现有加载、错误、空数据和分页状态继续使用真实逻辑。分页位于表格下方，视觉低调但仍可操作。
- 不添加搜索、刷新、导出、删除、详情按钮、统计卡片或新筛选项。

## 8. 图标资源

使用 Lucide 官方开源 SVG：

- `file-user.svg`：品牌图标。
- `layout-grid.svg`：任务台导航。
- `clock.svg`：历史记录导航（Lucide 主分支当前未提供 `history.svg`，使用规范允许的 clock 图标）。
- `circle-play.svg`：开始采集按钮。

资源保存到 `apps/web/src/assets/icons/`，通过本地 CSS mask 引用。SVG 只在开发阶段从 Lucide 官方仓库下载，页面运行时不访问网络。项目不安装 Lucide npm 包或其他图标框架。

## 9. 响应式策略

- 主要验收宽度为 1366–1920px。
- 任务台 Card 不随视口无限拉宽。
- 历史表格充分利用可用宽度。
- 低于桌面宽度时 Header、筛选器和任务台字段自然换行。
- 历史表格在必要时产生局部横向滚动，页面本身不产生无意义横向滚动。

## 10. 演示数据隔离

- 不把参考图中的日期、时间、状态、计数或任务记录写入组件、state、fixture、seed 或 API。
- 不添加 `mockData`、`demoTasks`、`sampleRecords` 或 fallback 记录。
- 现有测试中的 mock 数据属于既有测试基线，不因本次 UI 重构复制或扩展到生产代码。
- 历史接口为空时继续显示现有空状态。

## 11. 测试与验收

实施前通过测试锁定关键业务绑定和结构：

- 历史筛选仍使用原 status/mode 参数加载真实数据。
- 表格仍按 API 返回任务渲染，空态和分页保持可用。

## 12. 已知限制

- 原第二个行政区控件是原生 `<select multiple>`。为保护既有多选行为，不改成截图中的单行自定义下拉，因此不同操作系统下的原生选中样式可能与参考图略有差异。
- 指定机构模式具有参考图未展示的必需业务字段。这些字段必须保留，只能融入同一视觉体系。
- 现有历史分页必须保留，因此有多页数据时页面底部会比参考图多出低强调分页控件。
