# crawler-test-regressions 知识视图

> 本视图是 `crawler-test-regressions` Skill 的独立知识视图，只保留与"爬虫测试与修复验证顾问"职责相关的知识。来源身份、版本与许可证事实由共享证据层统一维护，本视图通过稳定证据卡 ID 引用，不复制原始来源元数据。

## 定位、触发与排除项

- **定位**：面向 Agent 的爬虫测试与修复验证顾问；依托固定版本资料、测试指南、故障案例和合规源码，结合已确认根因与项目验收标准，帮助 Agent 设计单元/集成/回放/契约测试、金标数据、故障注入、性能和安全回归；检查修复是否真正解决原问题、是否引入新问题、外部网站异常是否被错误计入项目自身测试失败。
- **不是**：项目测试体系的替代品；不替代领域 Skill 诊断根因。
- **触发**：用户要求检查测试与修复验证相关设计或故障；已确认问题需要形成回归测试、验证修复有效性、设计测试体系或判定发布阻断。
- **排除**：测试发现新的未知问题时退回 `crawler-triage-incidents`；toxiproxy 按主决策日志 §70 只作受控案例知识（不授权启动代理/影响环境/注入故障）；不替代领域诊断；不生成 `writing-plans`。

## 最低证据输入

- 项目上下文（处理 Stellaris 问题时为 `stellaris-crawler-context` 项目上下文包路径）。
- 已确认根因与方向（`crawler-triage-incidents` 分诊结论，适用时）。
- 相关代码、测试体系、依赖版本、验收标准、复现证据。
- 固定版本资料（批次 3：locust；批次 4：pact-specification、JSON-Schema-Test-Suite、toxiproxy、in-toto）。

## 知识主题与证据卡映射

### 单元/集成测试与断言

- 判断 Schema 校验语义、断言结构、测试套件组织是否符合固定版本行为；断言缺失、跨版本不一致是常见问题。
- 证据卡：[[TR-UNIT-001]]（Schema 校验语义作断言基础）、[[TR-UNIT-002]]（断言结构跨草案版本）、[[TR-UNIT-003]]（测试套件组织与可复现）。
- 依据固定版本：JSON-Schema-Test-Suite `tests/`、`output-tests/`。

### 回放测试与金标数据

- 判断金标数据比对、已保存证据验证是否符合固定版本行为；金标依赖实时抓取、回放测试缺失是常见问题。
- 证据卡：[[TR-REPLAY-001]]（金标数据比对）、[[TR-REPLAY-002]]（已保存证据验证）。
- 依据固定版本：JSON-Schema-Test-Suite `output-tests/`；in-toto 验证流程。

### 契约测试

- 判断契约测试语义、生产者/消费者接口一致性是否符合固定版本行为；接口漂移、契约不同步是常见问题。
- 证据卡：[[TR-CONTRACT-001]]（契约测试语义）、[[TR-CONTRACT-002]]（生产者/消费者接口一致性）。
- 依据固定版本：pact-specification `implementation-guidelines/`。

### 故障注入与性能测试

- 判断受控网络退化案例、toxiproxy 边界、负载测试基线是否符合固定版本行为；故障注入越界、性能基线不可比是常见问题。
- 证据卡：[[TR-FAULT-001]]（受控网络退化案例）、[[TR-FAULT-002]]（toxiproxy 准入边界）、[[TR-PERF-001]]（负载测试基线）。
- 依据固定版本：toxiproxy `toxics/`、`link.go`、`README.md`；locust `locust/`。

### 安全回归与发布阻断

- 判断安全回归验证、发布阻断硬门槛是否符合纪律；无结果证据宣称修复成功、关键回归失败放行是常见问题。
- 证据卡：[[TR-SEC-001]]（安全回归验证）、[[TR-SEC-002]]（发布阻断硬门槛）。
- 依据固定版本：主决策日志 §58；in-toto 验证流程。

## RED-GREEN 测试设计规则

- 修复前先形成能稳定暴露问题的失败案例（RED），运行确认失败。
- 修复获批实施后运行测试并保存结果证据（GREEN）。
- 测试必须可复现、有结果证据；无结果证据时不宣称修复成功。
- 外部网站异常与项目自身缺陷必须分离，不得把外部条件误计入项目测试失败。
- 金标数据与回放测试基于已保存证据，不依赖实时抓取。

## 发布阻断规则

- 安全或正确性硬门槛测试失败时，必须阻止通过（发布阻断）。
- 关键回归失败时不得放行。
- 无结果证据时不得宣称修复成功。
- toxiproxy 按主决策日志 §70：只作受控案例知识，不授权启动代理/影响环境/注入故障。

## 版本化判断规则

- 每条判断依据必须追溯到固定版本资料（ref＋Commit）、证据卡、上下文包条目或决策日志节号；只给仓库首页或没有版本的引用不满足要求。
- 明确区分事实、证据、综合推断与未知项；综合推断必须显式标记"推断"，不得伪装成资料中的确定结论。
- 不得因新技术更新默认要求升级；是否升级以证据和项目约束为准。
- 案例证据与工程证据不得单独升格为跨项目通用规范或确定根因。

## 输出、交接与禁止越权

- **输出**：可追溯测试范围、测试依据、通过/失败结果、未覆盖风险、发布阻断结论。
- **交接**：新未知问题→`crawler-triage-incidents`（退回分诊）；获准修复方向→`crawler-writing-plans-bridge`；领域根因→相应领域 Skill。
- **禁止越权**：不替代领域诊断根因、不宣称无证据的修复成功、不放行关键回归失败、不授权故障注入/启动代理、不生成 `writing-plans`、不初始化 Git、不记录敏感信息原件。
