## 1. 目标

把「单站点（安徽省级）已验证」推进到「多行政区真实校准 + 准确率门槛量化」，对齐冻结规格：

- **真实校准**：安徽 16 地市真实采集链路（多行政区任务 → 每地市真实官网），验证多行政区驱动的真实入口映射；
- **准确率门槛**：两名主要自然人选择准确率 ≥95%（§26.2）、人员—机构—岗位映射 ≥98%，用**离线金标测量**量化（先行，不依赖真实站点规模）；
- **金标扩展**：从当前 5 个 fixture 文件向 §27.1 目标（500 页面 / 31 省级 / 120+ 主机）推进的**第一阶段**（安徽本地优先）。

## 2. 现状差距（现场核验事实）

| # | 现状 | 差距 |
|---|---|---|
| 1 | `regionEntries` 仅 `340000 → www.ah.gov.cn`（安徽适配器） | **16 地市无真实入口映射**——多行政区任务每地市入口 fallback 到无效 regionCode |
| 2 | 安徽 16 地市官网为**独立域名**（`hefei.gov.cn`/`wuhu.gov.cn` 等，DNS 核验解析成功） | 不在已授权 `*.ah.gov.cn` 域内——**逐站真实抓取需授权** |
| 3 | 金标 fixture 仅 5 文件（collection/forbidden/leader-detail×2/robots） | 远低于 §27.1 目标（500 页面/31 省级/120+ 主机/50 完整领导结构） |
| 4 | 无准确率测量代码（无 precision/recall/F1 计算） | §26.2 门槛无法量化 |
| 5 | 金标回放用 `replay-driver`（fixtureUrl 模式） | 无「已知合格 URL 集合 vs 预测集合」的评估入口 |

**结论**：P4 含两个独立工作流——(A) 安徽 16 地市真实校准（需逐站授权，驱动侧增强）；(B) 离线金标准确率测量（无需新授权，纯本地）。

## 3. 设计决策（brainstorming 结论）

### 决策 D1：安徽 16 地市真实入口映射（校准驱动侧）

- 扩展安徽适配器 `regionEntries`：`340100→https://www.hefei.gov.cn/` … `341800→https://www.xuancheng.gov.cn/`（16 地市，DNS 已核验解析成功）；
- `regionEntries` 缺省时的 fallback 行为不改（无映射如实失败/标记）；
- 多行政区驱动 `runMultiRegionPipeline` 已支持按行政区传入 regionCode → 每地市复用已校准多机构链路。

### 决策 D2：地市真实抓取授权（逐站）

- **授权建议**：对安徽 16 地市政府官网（`*.gov.cn` 独立域名）执行只读校准 Canary（同 R-08/R-21 边界：只读、礼貌并发 ≤2、DNS-pinned SSRF、robots、不绕过访问控制）；
- **边界**：仅采集入口页 + 领导列表/详情页（如有）；每站单次少量请求；不改生产数据；
- 非授权范围内不做：批量抓取、性能压测、搜索提供器、其他省。

### 决策 D3：离线金标准确率测量（先行，无需授权）

- 新增 `packages/rules/src/evaluate.ts`（或 `packages/crawler/src/golden/evaluate.ts`）：
  - 输入：已知合格 URL 集合（金标 `golden.json`）+ 系统预测集合（回放 result_row）；
  - 输出：precision / recall / F1 / 两名主要自然人选择准确率 / 人员—机构—岗位映射准确率；
- 金标样本：安徽省级已校准（安徽省人民政府王清宪/王东伟已知答案）作为种子，逐步扩展；
- 测量脚本：`pnpm --filter @stellaris/rules exec tsx src/evaluate.ts --golden ... --result ...`。

### 决策 D4：金标 fixture 扩展（第一阶段安徽优先）

- `golden.json` 声明已知答案（机构→两名主要自然人→URL），供评估脚本比对；
- 安徽省级 + 部门机构真实采集结果作为首批金标样本（基于 R-21/R-27/R-37 已验证结果）；
- 不一次性追求 500 页面（§27.1 是长期目标）；本阶段目标是**测量基础设施可用 + 安徽种子达标**。

### 决策 D5：边界

- 真实抓取仅限安徽 16 地市（逐站授权）；其他省/机构适配器不扩展；
- 准确率测量为离线金标，不依赖真实站点规模；
- 不改数据合同/证据链/驱动核心语义；P1 站点画像/并发闸复用；
- 不引入新依赖（R-06）。

## 4. 验收映射（§26.2/§30）

| 验收项 | 达成方式 |
|---|---|
| 两名主要自然人选择准确率 ≥95% | D3 离线金标测量 + 安徽种子样本 |
| 人员—机构—岗位映射准确率 ≥98% | D3 测量 |
| 已知合格 URL 总召回率 ≥90% | D3 测量（金标集合召回） |
| 多行政区真实 Canary | D1/D2 安徽 16 地市校准 |

## 5. 打开问题（建议分诊）

1. **16 地市官网是否有可采集的领导信息页**：多数地市官网结构不同，可能部分无领导页（如实「无领导信息」）——校准过程中发现并记录，不强行适配；
2. **准确率阈值以哪种统计口径**：两名主要自然人「选择准确率」= 预测的人选是否命中金标人选（人名相等）——建议此口径；
3. **金标扩展速度**：首批仅安徽种子（≤20 样本）还是尝试更多（涉及真实抓取量）——建议先安徽种子，达标后视情况扩展。
