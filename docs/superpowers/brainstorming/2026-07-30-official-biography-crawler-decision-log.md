## 1. 产品目标与边界

- 将 `official-biography-evidence` 中适用于自动化系统的规范，改装为真正的 Web 爬虫系统，用于批量采集中国各行政区官方网站中的个人简介信息 URL（岗位信息 URL）。
- 系统核心竞争力是网页发现、快速抓取、结构解析、候选筛选、严格准入、恢复搜索和自动复核，不围绕非核心管理功能扩张。
- 网站交互必须简单；能够由后台自动完成的工作，不要求用户手工操作。
- 参考图只借鉴“入口简单、核心动作明确”的产品原则，不照搬品牌、布局或视觉细节。
- 现有 Skill 是 Agent 行为规范，不是自动爬虫框架。新系统继承规范语义，不复制 Agent UUID、聊天回执、Skill 加载证明等 Agent 专属运行模型。
- 新系统不使用大模型进行页面语义判断，采用纯规则系统。

## 3. 任务范围与交互

- 首版支持多行政区批量任务，而不是只处理单个行政区，也不要求首版直接执行全国全量一键运行。
- 目标选择同时支持：

  - 选择上级行政区后自动展开下级；
  - 用户取消部分地区；
  - 用户上传指定行政区清单。

- 任务可配置展开截止层级：默认到区县，可按需继续展开至乡镇和街道。
- 支持两种采集模式：

  - 默认模式：完整机构库存＋每个机构两名主要自然人；
  - 定向模式：指定机构或人员。

- 首版为按需批量任务：用户创建任务后后台排队执行，支持暂停、续跑和失败恢复；不做定时更新或持续监测。
- 首版仅服务用户本人，采用本地或内网单用户部署；不设计登录、权限、团队协作、多租户或公网运营功能。
- 结果交付采用：简洁网页结果表＋单表 Excel 下载。
- 网页只突出任务状态、进度、严格合格数、空 URL 数和简洁结果表；详细证据保存在后台。

## 4. 自动复核与失败原则

- 系统完全自动化复核，不要求用户逐条人工确认。
- 复核必须是独立作业：重新访问非空 URL；对空 URL、不合格 URL 和冲突项重新搜索；重新计算域名、页面类型、当前性和更优候选。
- 无法严格确认时不以新闻、媒体、Wiki、首页或栏目页填充；保留可确认的人员、岗位和中文状态，最终 URL 留空。
- 外部搜索引擎或搜索 API 只用于发现线索；搜索结果页和摘要永远不能作为最终 URL 或最终证据。

## 5. 总体架构与技术栈

- 采用“模块化单体＋独立 Worker”架构：一个代码库、一套部署，但任务、HTTP 抓取、Playwright、Recovery、复核和导出使用可独立重试的作业边界。
- 部署方式：Windows 主机运行 Docker Desktop，后台使用 Linux 容器。
- 统一语言与生产运行时：TypeScript 6.0＋Node.js 24 LTS；使用 `pnpm` workspace 和锁文件固定精确依赖版本。
- 前端：React 19＋Vite 8.1＋TanStack Query 5＋TanStack Table 8＋原生 EventSource；样式使用 CSS Modules 和 CSS Custom Properties，复杂无障碍控件按需使用 Radix UI Primitives。
- 前端不使用 SSR、Next.js、Tailwind、整套 UI 主题库、Redux 或 Zustand；首版只实现已选的单页任务工作台。
- API：Fastify 5.7，使用 REST＋SSE；边界合同固定为 TypeBox＋JSON Schema＋Ajv。
- 数据层：PostgreSQL 18＋Kysely 0.29＋`pg`；数据库迁移使用 Kysely migration provider；持久队列继续使用 Graphile Worker，不引入 Redis。首版不采用选型时仍为 1.0 RC 的 Drizzle。
- 爬虫运行时：Crawlee 3.16 的 `CheerioCrawler` 作为 HTTP 快速通道，`PlaywrightCrawler`＋Playwright 1.62 Chromium 作为按需升级通道，Cheerio＋parse5 负责 HTML/DOM 事实解析。
- Excel：ExcelJS 生成唯一单 Sheet `.xlsx` 和可点击岗位 URL。
- 证据：Node.js `fs`/`crypto`＋Zstandard，在 D 盘以 SHA-256 内容寻址保存。
- 安全出口：TypeScript URL/DNS 策略层负责逐跳验证，Squid sidecar 负责强制代理和第二层 ACL；API 与 Worker 禁止绕过出口直连公网。
- 可观测性：Pino＋OpenTelemetry JS＋`prom-client`；首版不强制增加 Grafana、Loki 或 Elasticsearch。
- 测试与基准：Vitest 4.1、React Testing Library、`fast-check`、Testcontainers、Playwright Test 1.62 和 k6。
- 生产环境由 Fastify 提供构建后的 React 静态页面，Vite 只作为开发服务器；同一后端镜像通过不同入口运行 API、HTTP Worker、浏览器 Worker、规则、Reviewer 和导出作业。
- 明确不采用：NestJS、Python 爬虫运行时、GraphQL、WebSocket、RabbitMQ/Kafka、微服务和 Kubernetes。
- 原 Skill 中继续适用的枚举、Schema、候选排名、准入规则和测试语义改造成版本化、声明式规则包；不为复用旧 Python 文件而保留 Agent 运行模型。
- 预期基础组件：

  - 简洁 Web/UI 与任务 API；
  - 持久化任务队列；
  - HTTP Worker 池；
  - Playwright Worker 池；
  - 规则与自动复核作业；
  - PostgreSQL；
  - 分级证据文件库；
  - Excel 导出器。

## 7. 抓取模式与并发控制

- 使用站点画像驱动的自适应路由：

  - 新域名或新路径模式先走 HTTP；
  - 正文缺失、Hash 路由、动态加载或页面结构不完整时升级 Playwright；
  - 记录域名＋路径模式、页面家族、抓取模式、等待条件、可阻断资源、成功率和平均耗时；
  - 同站同路径家族后续直接进入已验证的正确 Worker；
  - 定期抽样复查画像，防止网站改版。

- 使用健康度驱动的自适应并发：

  - 单域名 HTTP 初始并发 2；
  - 健康时逐步提升至 4，最高 8；
  - 全局 HTTP 根据 CPU、内存和连接数在允许范围内调节；
  - 触发 403、412、429、连续 5xx、WAF、超时或延迟恶化时降低该域并发并指数退避；
  - 一个慢站不得阻塞其他健康域名；
  - 大量 URL 集中于同一慢站时标记“站点限速”，不以过载请求强行追赶 SLO；
  - 遵守 `robots.txt`。

## 8. URL Frontier 与搜索发现

- 采用分阶段定向 Frontier，不做宽泛全站遍历。
- 链接优先级：

  - P0：官方机构目录、当前领导集合页、已知个人入口；
  - P1：领导信息、领导分工、机构领导、负责人、个人简历；
  - P2：政府信息公开、机构信息、法定主动公开内容、部门详情；
  - P3：站内搜索、Sitemap、外部搜索发现的官方候选；
  - P4：Recovery 的替代入口和同区域成功 URL 模式。

- 默认预算：

  - 首次发现深度最多 4 层；
  - 单机构首次最多 30 个唯一页面；
  - Recovery 最多追加 30 个页面；
  - 普通分页默认不连续遍历；
  - 新闻、工作动态、附件、视频、图片和非关联域名不继续扩散。

- 满足机构身份、完整领导结构、两名主要自然人、候选严格排序、更优个人入口检查和独立复抓后立即停止，不为用满预算继续抓取。
- 外部搜索采用可插拔提供器：

  - Brave Search API 为默认实现；
  - Google Programmable Search API 可选；
  - 本地 SearXNG 可选；
  - 接口允许以后增加其他合法中文搜索提供器；
  - 统一保存查询、提供器、排名、标题、摘要、URL、时间和耗时；
  - 搜索结果缓存、跨提供器去重，官方域名优先；
  - API Key 只存本机环境变量或 Docker Secret。

## 9. 缓存与证据保存

- 证据采用分级保存：

  - 所有访问保存 URL、时间、状态、正文文本、内容哈希和链接关系；
  - 最终候选、动态页面、访问异常和冲突页面额外保存原始 HTML 或截图。

- 跨任务缓存采用分级缓存＋正式任务条件复验：

  - 同一任务的相同 URL 直接复用；
  - 机构目录、栏目导航和站点画像缓存 7 天；
  - 外部搜索结果缓存 24 小时；
  - `robots.txt` 缓存 24 小时；
  - 访问失败负缓存 5–15 分钟；
  - 领导集合页、领导详情页和个人简介页每次正式任务必须重新验证；
  - 优先使用 ETag/If-None-Match，其次 Last-Modified/If-Modified-Since；
  - 304 可沿用旧正文，但必须生成本次真实复验事件；
  - 不支持条件请求时重新下载正文；
  - Reviewer 不得只读历史数据库后直接批准。

## 10. 站点适配与页面抽取

- 采用“通用规则＋声明式站点家族适配器＋区域成功模式积累”。
- 四层处理：

  1. 通用 DOM 事实抽取；
  2. 站点家族适配器；
  3. 本地区成功模式复用；
  4. 通用规则回退与 Recovery。

- 适配器使用可审计的 JSON/YAML，描述 host/path 模式、渲染模式、DOM selector、必要信号和禁止信号；不使用任意脚本绕过准入。
- 从成功页面积累路径模式、稳定 DOM、常见领导栏目、个人入口、渲染需求、动态接口、平均耗时和成功率。
- 自动发现模式先作为运行时画像，经过多个页面交叉验证后才可提升为正式可复用适配器。
- 不能只依赖文章正文抽取；必须保留原始 DOM 中的表格、列表、卡片、姓名链接、头像链接、官方顺序和上下文标题。
- 动态站点采用“被动发现公开只读接口＋验证后复用”：

  - Playwright 正常打开页面时记录页面自己发出的 XHR/Fetch；
  - 只考虑官方域名或已验证官方关联域名中的公开请求；
  - 请求必须无登录、无私人 Cookie、无验证码，只读取公开信息；
  - 只允许 GET 或已经证明为幂等查询的 POST；
  - 保存请求 URL、方法、公开参数、响应类型、结构指纹、页面关系和字段位置；
  - 接口响应必须与渲染后的公开领导栏目一致，并能回溯到公开网页入口；
  - 独立复验一致后才进入可复用接口画像；
  - 后续可以接口快速读取，但仍需执行规则验证与公开页面复验；
  - 接口失效时自动回退 Playwright；
  - 禁止猜测接口、扫描隐藏管理端点、绕过登录/验证码/权限/WAF、调用写操作或保存私人凭据；
  - 不能只凭接口数据输出无法在官方公开页面定位的最终 URL。

## 11. 候选排序与最终准入

- 采用“发现阶段打分、最终阶段硬性准入”。
- 发现分数只用于 Frontier 优先级；新闻、动态、附件、非官方域名等可以获得强负分或直接不入队。
- 最终 URL 必须同时通过：

  1. 官方域名关系；
  2. 五类允许页面类型之一；
  3. 支持目标自然人；
  4. 支持目标机构；
  5. 支持目标正式岗位；
  6. 当前性成立；
  7. 已检查更优个人入口；
  8. 独立复抓一致；
  9. 没有禁止页面信号。

- 任何硬门槛都不能由相关度分数补偿。

## 12. 当前性

- 采用当前性证据图与严格优先级。
- 最强证据：目标人员和岗位出现在当前领导集合。
- 强证据：个人详情页由当前领导集合直接链接。
- 可接受补充：现行领导分工页、官方机构近期现任信息、上级官方当前领导页面。
- 页面发布日期、HTTP Last-Modified、搜索摘要、普通活动报道和任免新闻只能作为弱辅助，不能单独确认当前性。
- 当前状态至少区分：

  - CURRENT_COLLECTION_MEMBER；
  - DETAIL_LINKED_FROM_CURRENT_COLLECTION；
  - RECENT_CURRENT_OFFICIAL_EVIDENCE；
  - DETAIL_NOT_IN_CURRENT_COLLECTION；
  - DETAIL_COLLECTION_CONFLICT；
  - CURRENTNESS_UNRESOLVED。

- 详情页未出现在当前集合、详情与集合冲突或当前性未解决时必须 Recovery；仍无法解决时 URL 留空。

## 13. 完整领导结构与两名主要自然人

- 采用“完整领导结构＋机构类型声明式规则引擎”。
- 选人前必须形成：全部当前可见领导、每人全部机构内岗位、官方顺序、党政关系、主持日常工作信息、专职/常务属性和页面证据。
- 按党委、政府、人大、政协、纪委、监委、法院、检察院、政府部门、公安机关、开发区、乡镇街道、群团和事业单位分别定义选择规则。
- 同一自然人不得同时占两名主要负责人槽位。
- 纪委和监委即使合署也分别输出。
- 同一人跨机构任职时按机构分行；同一机构内的正式兼任岗位可以合并显示。
- 官方网页顺序只作为最后的确定性 tie-breaker。
- 第二人无法确认时进入 Recovery；仍无法确认则留空并记录具体中文原因。
- “主持工作”必须保留原正式岗位和限定，不得擅自改写成局长或书记。
- 正式岗位空缺时输出中文“空缺”，不得用普通副职自动顶替。

## 14. 网络重试与业务 Recovery

- 采用“有限网络重试＋改变策略的业务 Recovery”双层机制，两者分别记账、分别统计。
- 网络重试只处理瞬时传输故障：
  - DNS、TLS、连接重置、连接/读取超时、502、503、504 默认最多重试 2 次，并使用带随机抖动的指数退避；
  - 429 或 503 存在 `Retry-After` 时遵守服务端等待时间，并同步降低该主机并发；
  - 404、410 不进行普通网络重试；
  - 401、403、412、WAF 或疑似阻断不得反复轰击；仅在页面特征表明浏览器能够正常公开访问时允许一次 HTTP → Playwright 升级，失败后记录中文原因并停止该路径；
  - 不绕过登录、验证码、WAF 或访问权限。
- Playwright 使用明确的 DOM、目标 XHR/Fetch 或业务字段作为页面就绪信号，不使用固定长等待，也不以 `networkidle` 作为默认完成条件。
- 业务 Recovery 在以下情况触发：URL 为空、页面类型被禁止、人员/机构/岗位不匹配、当前性冲突、尚未检查更优入口、第二名主要自然人无法确认，以及重点机构出现双空结果。
- Recovery 必须改变发现路径或验证策略，不得只是重复刷新原页面。默认顺序为：
  1. 已缓存且仍有效的站点画像、机构目录和当前领导入口；
  2. 政府信息公开、机构信息、领导信息和分工目录；
  3. 已被公开页面触发且通过验证的只读接口；
  4. Sitemap 与站内搜索；
  5. 限定官网域名的外部搜索；
  6. 机构简称、人员姓名与正式岗位组合搜索；
  7. 上级官网当前领导入口；
  8. 同地区已经验证成功的 URL/栏目模式。
- 单机构首轮最多抓取 30 个页面，Recovery 最多再追加 30 个页面；达到证据闭环立即停止，不为耗尽预算继续抓取。
- 前台优先在 30 秒内展示已经确认的结果；较慢的 Recovery 可在任务后台继续，但必须显示具体中文状态。耗尽策略与预算后宁可留空，也不得用新闻、媒体、百科、搜索结果或栏目首页补位。

## 15. 盲审式双通道 Reviewer

- Reviewer 是独立的证据生产与准入判断作业，不是读取 Collector 结论后盖章的状态机。
- Reviewer 只接收最小核验目标：行政区、机构、自然人、正式岗位、待复核 URL，以及当前性判断必需的上游入口 URL；不接收 Collector 的得分、页面类型结论、准入结论或分析说明。
- 每个最终候选使用不同于 Collector 的请求唯一键进入 Reviewer 队列，保证同一 URL 能产生新的真实网络事件。
- HTTP 页面重新请求；动态页面使用新的 Playwright `BrowserContext`，不得共享 Collector 的 Cookie、浏览器缓存、页面对象、DOM 或会话状态。
- Reviewer 使用同一套已发布且带版本号的硬规则，但必须从复抓响应重新生成 DOM/文本事实、页面类型、人员、机构、岗位、当前性、链接关系和禁止信号，不得沿用 Collector 的抽取结果。
- 如果候选当前性依赖当前领导集合页、分工页或其他上游页面，Reviewer 必须同时复抓并核对该依赖页面。
- Collector 与 Reviewer 必须在自然人、机构、正式岗位、页面类型、当前性和最终 URL 六方面一致，并且所有硬门槛通过后才可准入。
- 任一硬门槛分歧都触发 Recovery；Recovery 后仍不一致则 URL 留空，并保存具体中文分歧原因。
- Reviewer 在候选形成后立即流式启动，不等待整个行政区发现结束。调度器动态预留约 20% HTTP 能力和最多 1 个浏览器页面给 Reviewer；空闲资源允许互借，但不得让复核长期饥饿。
- Reviewer 只复核最终候选及其关键上游证据，不重复完整的机构发现与全站遍历。

## 16. 证据事实与规则结论分离的结构化流水线

- 采用“不可变证据层＋可重新计算的规则结论层”。真实网络事实和页面快照不得被后续阶段覆盖；页面判型、实体关联、当前性、选人和准入结论可以随规则版本重新计算。
- 流水线阶段依次为：
  1. 任务范围与规则版本冻结；
  2. 机构清单冻结；
  3. URL Frontier 与抓取意图生成；
  4. HTTP/Playwright 真实网络抓取；
  5. 页面快照、DOM 事实与链接事实生成；
  6. 页面类型与禁止信号判定；
  7. 人员、机构、岗位、当前性和链接关系证据图；
  8. 完整领导结构组装；
  9. 两名主要自然人选择；
  10. 最终 URL 硬门槛判断；
  11. 未闭环结果进入 Recovery；
  12. 盲审 Reviewer；
  13. 网页结果与 Excel 输出映射。
- 每个阶段只产生自己的结构化记录，不允许输出阶段越过前置阶段临时猜测或补值。
- 核心中间对象至少包括：任务范围、机构快照、抓取意图、抓取事件、页面快照、页面事实、页面判型、证据断言、领导结构、槽位决策、候选准入、Recovery 决策、Reviewer 决策和输出投影。
- 每条记录带任务 ID、阶段/作业 ID、输入记录引用、规则版本、开始/结束时间和输出记录引用，形成可查询的因果链。
- 每次网络重试和 Reviewer 复抓都是独立抓取事件；同一正文可通过内容哈希去重，但不得把历史访问伪装成本次网络访问。
- 规则升级时可以从不可变页面快照重新执行判型及后续阶段；涉及人员是否仍在任的正式任务仍须重新访问官网。
- Worker 运行链使用统一 Trace/Span 关联任务、机构、URL、抓取、Recovery、Reviewer 与导出耗时，但运行遥测不代替业务证据。

## 17. PostgreSQL 与内容寻址证据库

- 采用“PostgreSQL 关系型业务索引＋`jsonb` 可变事实＋D 盘内容寻址证据库”的混合存储。
- PostgreSQL 普通字段保存任务、行政区、机构、人员、岗位、URL、状态、时间、规则版本、哈希和各硬门槛结果，用于高频筛选、关联、分页和导出。
- 官网结构差异较大的 DOM 事实、判型特征、适配器参数和扩展属性使用 `jsonb`，只对实际查询路径建立必要索引。
- 原始 HTML、完整正文、公开 JSON 响应和截图不直接堆入 PostgreSQL，保存到 `D:\StellarisData\evidence`；Excel 等导出文件保存到 `D:\StellarisData\exports\<任务ID>`。
- 对未压缩原始字节计算 SHA-256，并以 `sha256/<前两位>/<次两位>/<完整哈希>.<类型>.<压缩格式>` 内容寻址；同一正文跨任务和 URL 只保存一份。
- 内容去重不合并网络事件。每次 Collector、重试、Recovery 和 Reviewer 访问仍产生独立 `fetch_attempt`，再分别引用相同或不同的 `document_snapshot`。
- `document_snapshot` 至少保存内容哈希、MIME、字符集、原始大小、压缩大小、相对安全路径和抓取事件引用。
- HTML、文本和 JSON 使用快速压缩；PNG 等已经压缩的截图不重复压缩。
- 文件先写入同盘临时文件，完成长度和哈希校验后原子改名；读取时校验哈希，并提供引用缺失与孤立文件完整性扫描。
- 数据库只允许记录证据根目录下的相对路径，禁止任意绝对路径和路径穿越。
- 数据表按职责拆分：
  - 范围层：`task_run`、`target_scope`、`institution_snapshot`；
  - 抓取层：`crawl_intent`、`fetch_attempt`、`document_snapshot`、`link_edge`；
  - 事实层：`page_fact`、`entity_assertion`、`currentness_assertion`；
  - 业务层：`leadership_snapshot`、`role_assignment`、`slot_decision`、`url_candidate`；
  - 控制层：`recovery_attempt`、`review_job`、`review_decision`；
  - 输出层：`result_row`、`export_artifact`；
  - 复用层：`site_profile`、`public_api_profile`、`rule_version`。

## 18. 网页结果与单 Sheet Excel 输出

- 网页主表保持精简，只显示：行政区、机构、岗位、现任人员、当前状态、岗位信息 URL、采集结果和“查看证据”操作。
- 页面类型、Collector/Reviewer 访问时间、当前领导集合关系、空 URL 原因和关键证据在行详情中按需展开，不挤入主表。
- 单 Sheet Excel 工作表名统一为“岗位信息采集结果”，字段固定为：
  1. 行政区划代码；
  2. 省；
  3. 地市；
  4. 区县/县级市；
  5. 乡镇/街道；
  6. 机构；
  7. 岗位；
  8. 现任人员；
  9. 当前状态；
  10. 岗位信息URL；
  11. 页面类型；
  12. 采集结果；
  13. 采集时间。
- 行政区划代码按文本保存，避免前导零丢失；不适用的行政层级字段留空。
- 一个机构的两名主要自然人各占一行，但网页和 Excel 均不得显示 `PRIMARY_1`、`PRIMARY_2` 等槽位代码。
- “当前状态”只使用中文：正式在任、代理中、主持工作、暂未确认、空缺。
- “页面类型”只使用中文：个人简介页、个人卡片页、领导分工页、当前领导详情页、当前领导集合页；URL 为空时页面类型也留空。
- “采集结果”使用用户可理解的中文结论，例如：已找到并复核、完整搜索后无合格URL、当前人员未确认、岗位空缺、官网访问受限。
- 岗位信息 URL 单元格为可点击超链接；只有 Reviewer 通过的 URL 才能进入该栏。
- 不输出内部 ID、英文枚举、相关度分数、规则分析过程、重试次数、证据数组、Worker 状态或其他内部字段。
- 删除原 Skill 模板中与本项目无关且始终为空的任前公示、代理任命、选举或任命、离任四类 URL 列。
- 网页筛选、排序和 Excel 导出读取同一份已复核 `result_row`，不得维护两套结果逻辑。

## 19. 任务生命周期、幂等与崩溃恢复

- 采用“PostgreSQL 持久业务状态＋Graphile Worker 作业队列＋阶段幂等键”，首版不额外引入 Redis。
- 用户可见任务状态统一为中文：待开始、正在准备、正在抓取、正在恢复搜索、正在复核、正在生成结果、已暂停、正在取消、已取消、已完成、部分完成、失败。
- 暂停时立即停止派发新抓取和 Reviewer 作业；活动请求在短暂宽限期内完成证据写入，超时后安全中止。关闭 Docker 后仍保持暂停。
- 继续时只恢复未完成、可重试或租约过期的作业；已经完整提交的阶段不重复生成，但当前领导页面仍遵守正式任务网络复验规则。
- 取消采用协作式中止：停止新作业、向活动 Worker 传递取消信号、完成临时文件和证据收尾。已取消任务不能直接恢复，只能复制为新任务。
- Worker 或容器异常退出后，锁定作业在租约/锁定时间过期后自动重试；正常退出先停止领取新作业，再等待活动作业结束。
- 作业结果先在事务中提交业务记录，再确认队列作业完成；文件使用临时写入、哈希校验和原子改名，避免半成品被视为成功证据。
- 每个阶段作业使用包含任务 ID、机构 ID、阶段、规范化 URL、作业用途和规则版本的幂等键；数据库唯一约束负责最终防重。
- “开始采集”提交包含客户端请求键，双击或网络重发只创建一个任务；用户主动“重新采集”生成新的任务 ID 和请求键。
- Graphile Worker 只负责可靠投递、并发领取、重试与退避；永久作业尝试、阶段状态和业务证据保存在本项目自己的表中，不依赖队列完成记录永久存在。
- “已完成”表示所有冻结机构均到达终态；完整搜索后无合格 URL、当前人员未确认和岗位空缺仍属于可信完成。
- “部分完成”表示成功形成结果，但仍有机构因官网持续阻断或必要外部服务不可用而无法走完流程。
- “失败”仅表示内部错误使可信输出无法形成，例如数据库/证据完整性错误、规则版本缺失或导出校验失败。
- 进度使用真实计数，不显示虚假线性百分比，例如：已处理机构数/冻结机构总数、已复核岗位数、Recovery 中数量和官网受限数量。

## 20. 性能、正确性与回归基准

- 采用“固定回放基准＋真实官网 Live Canary＋正确性金标”三层体系，分别测量确定性内部性能、真实网络端到端速度和采集质量。
- 首版固定回放金标集包含 500 个已标注页面，覆盖全国 31 个省级行政区和不少于 120 个官网主机：
  - 250 个五类合格页面；
  - 150 个新闻、工作动态、栏目首页、机构首页、媒体等禁止页面；
  - 100 个动态加载、页面冲突、过期详情、404、阻断等困难样本；
  - 另选不少于 50 个完整机构领导结构，验证两名主要自然人的选择规则。
- 本地回放服务器模拟静态 HTML、动态渲染、XHR、超时、429、503 和慢响应；不访问互联网，保证代码版本之间可重复比较。
- 真实官网 Canary 覆盖静态站、动态站、公开接口站和不同地区站点家族，遵守 `robots.txt` 与单域限速，并分别报告冷缓存与热缓存结果。
- 性能目标：
  - 首个已复核结果：P50 ≤ 12 秒、P95 ≤ 30 秒、P99 ≤ 45 秒；
  - 100–300 个已知候选页面批次：P50 ≤ 35 秒、P95 ≤ 60 秒、P99 ≤ 90 秒；
  - 纯内部抽取、判型和规则计算：P95 ≤ 100 毫秒/页、P99 ≤ 250 毫秒/页；
  - 峰值容器内存不超过 8 GB；
  - OOM、证据丢失和数据库死锁为 0。
- 指标必须分开记录外部官网等待、礼貌限速、搜索服务、HTTP 抓取、Playwright 渲染、规则抽取、Reviewer 和 Excel 导出耗时。
- 正确性发布门槛：
  - 禁止页面进入最终 URL 为 0；
  - 非官方域名进入最终 URL 为 0；
  - 未经 Reviewer 的 URL 进入输出为 0；
  - 已知合格 URL 总体召回率 ≥90%；
  - 未见网站家族召回率 ≥85%；
  - 页面类型宏平均 F1 ≥95%；
  - 人员—机构—岗位映射准确率 ≥98%；
  - 两名主要自然人选择准确率 ≥95%；
  - 当前性冲突触发 Recovery 或留空为 100%。
- 回归门槛：任一禁止 URL 泄漏立即阻止发布；召回、岗位映射或选人准确率下降超过 1 个百分点阻止发布；固定回放 P95 连续三次比基线慢 10% 以上阻止发布。
- Live Canary 连续五轮至少四轮满足 60 秒目标；外部官网异常单独标记，但保留原始统计，不删除慢样本美化成绩。
- P50、P95、P99、失败率、页面收获率、目标召回率、HTTP→浏览器升级率、Recovery 成功率和 Reviewer 分歧率均进入基准报告，不能只展示平均值。

## 21. 安全出口、URL 规范化、爬虫陷阱与测试分层

- 采用“统一安全出口＋双层 URL 身份＋硬预算陷阱控制”。HTTP 与 Playwright 的站外请求统一通过项目内安全出口，Worker 不直接访问互联网。
- 只允许 `http`、`https`；拒绝 URL 用户名/密码及 `file:`、`data:`、`ftp:`、`javascript:`、`blob:`、`ws:` 等协议。
- 新网站默认只允许 80、443；其他端口必须由已验证官网适配器明确放行。
- 每次连接前解析全部 A/AAAA 地址，拒绝本机、回环、私有网段、Docker 内网、宿主机别名、链路本地、组播、保留地址、云元数据地址和 IPv4 映射 IPv6 等绕过形式。
- DNS 解析结果在单次连接内固定；最多跟随 5 次重定向，每一跳重新校验协议、域名、端口和 IP，禁止客户端先自动跳转后补检查。
- Playwright 的 iframe、脚本、XHR、Fetch 和子资源使用相同安全策略；图片、字体、视频继续默认阻断。
- URL 同时保留：页面实际出现的 `original_url`、解析后的 `fetch_url`、只用于去重和陷阱识别的 `canonical_key`；规范化不得覆盖原始证据。
- 使用 WHATWG URL 解析规则处理域名大小写、IDN/Punycode、默认端口和路径点段。
- 只删除明确追踪参数；业务参数、签名参数和顺序敏感参数保留。普通 fragment 不参与网络去重，已确认的 SPA hash 路由单独生成 `client_route_key`。
- 默认拒绝或降级无限日历、筛选/排序/打印/移动版/会话组合、重复路径段、重定向环、同正文大量 URL、无限分页、超长 URL 和大量低价值路径变体。
- 陷阱硬限制包括：URL 默认最长 2048 字符、参数最多 8 个、同一路径模板低价值变体最多 20 个，并继续遵守深度 4、首轮 30 页、Recovery 追加 30 页预算。
- 文本/HTML/JSON 解压后默认最多 10 MB，单页面允许资源总量默认最多 25 MB；响应头、DOM 节点数和脚本时间设硬上限；PDF、压缩包、视频和普通附件默认不下载。
- 原始 HTML 只作为证据保存，网页默认展示转义文本和结构化事实；HTML 预览必须禁脚本、禁网络并置于沙箱；证据文件名只使用内容哈希。
- 测试分层包括：
  - URL/IP/判型/硬门槛/选人单元测试；
  - 畸形 URL、编码、IPv6、重定向和参数顺序属性测试；
  - DNS rebinding、私网跳转、429、503、超大响应、压缩炸弹、无限分页和 robots 集成测试；
  - 从任务创建到 Reviewer 与 Excel 的回放端到端测试；
  - 只读真实官网 Canary。
- 任一 SSRF、路径穿越、未转义 HTML、越权请求或爬虫陷阱回归都阻止发布。

## 22. 首版网页信息架构与视觉方向

- 用户选定三套原创视觉方案中的第 1 种“范围驱动任务台”，作为后续实现的唯一首版视觉基线。
- 页面采用全宽单页工作台，不照搬参考图的品牌、蜘蛛图形、蓝色渐变、网格背景、居中大卡片、页眉构图或具体间距。
- 视觉基调为暖白底、深灰正文、低饱和青绿色主色、浅灰绿色分隔线；圆角克制，几乎不使用阴影，不使用装饰插画、营销 Hero、仪表盘图表或多层卡片。
