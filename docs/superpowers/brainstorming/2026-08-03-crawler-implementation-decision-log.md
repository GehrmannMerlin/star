## R-01 数据存储目录改到 E 盘（2026-08-03 批准）

- **用户明确指令**：数据卷不挂载 D 盘，直接在 E 盘新建文件夹并挂载到该文件夹上。
- **覆盖的设计条款**：规格 §17 证据目录 `D:\StellarisData\`、§24.3 与主决策日志 §30/§31 "Docker 与证据优先 D 盘"。
- **新基线**：Docker 数据卷（PostgreSQL）挂载到 `E:\StellarisData\postgres`；后续证据库 `evidence\` 与导出 `exports\` 也以 `E:\StellarisData\` 为根（与规格 §17.1 的目录结构保持一致，仅盘符从 D 改为 E）。
- **原因**：用户明确选择；E 盘当前可用约 240 GiB，充足。
- **影响**：Docker Compose 卷定义、证据包路径配置、导出路径配置均以 `E:\StellarisData\` 为根。
- **边界**：不迁动既有 Docker Desktop WSL 磁盘（仍按主决策日志 §30 位于 E:\DockerDesktopWSL）；只影响本项目新产生的数据卷与证据。

## R-03 网站下一阶段采用单地区、单机构真实纵向闭环（2026-08-03 批准）

- **用户明确批准**：后续爬虫网站以“证据优先的纵向切片模块化单体”为主方向，下一阶段先完成一个单地区、单机构的真实端到端闭环，不先横向铺满所有包，也不先制作脱离真实后端的完整 UI。
- **下一阶段目标链路**：任务输入 → 范围与机构冻结 → URL 意图 → HTTP 优先抓取 → 必要时 Playwright 升级 → 不可变证据入库 → 页面事实抽取 → 完整领导结构 → 两名主要自然人槽位 → 五类页面与九项硬门槛 → Recovery → 隔离 Reviewer → `result_row` → 网页结果与单 Sheet Excel。
- **架构边界**：19 个项目 Skill 继续作为 Agent 的知识、诊断、评审和规划层，不成为网站运行组件；生产运行时使用 TypeScript 代码、声明式规则、数据库约束和 Worker 实现业务语义，不在运行时读取 Skill 文档替代规则代码。
- **实施顺序**：先建立可验证地基和单机构闭环，再扩展多行政区、完整机构库存、任务控制、并发、性能与运维能力。
- **非目标**：本决议不授权立即修改业务代码，不等于批准具体实施计划，也不改变冻结规格中关于纯规则判断、证据优先、Reviewer 隔离、禁止页面类型、安全出口和单 Sheet Excel 的约束。
- **详细设计**：`docs/superpowers/specs/2026-08-03-crawler-vertical-slice-design.md`。该文档在用户复核前属于依据本决议展开的设计规格，不把未获批准的推导写成新决议。

## R-09 Playwright 渲染验证授权（2026-08-03 批准）

- **用户明确批准**：对 R-08 同一 Canary 目标（安徽省人民政府官网 `https://www.ah.gov.cn/`）执行 Playwright 渲染验证，作为 R-08 的延伸。
- **背景（R-08 Canary 结论）**：领导详情页 `/content/column/6784021?liId=N` 的 HTTP 返回为整页导航而非个人简历，简历内容由 JS 动态渲染；精确命中规格 §10.2 升级条件"领导列表由脚本动态加载"。
- **验证目的**：确认"HTTP → 升级条件 → Playwright 渲染 → 页面事实抽取 → 判型"链路在真实动态站点上成立，为多机构模块的浏览器升级 Worker 设计提供确定性。
- **执行边界（只读，同 R-08）**：仅渲染已授权的同一批 URL（`/szf/index.html` 与 2 个 `liId` 详情页）；遵守 robots（站点无 robots.txt，默认允许）；单域礼貌；不登录、不解验证码、不绕过 WAF/访问控制；图片/字体/视频默认阻断（规格 §23.3）；浏览器不直连 PostgreSQL/API（规格 §6.3）。
- **Playwright 依赖**：`playwright` 1.62.1 已在 `packages/crawler` 依赖中；Chromium 浏览器二进制若本机未安装，需在验证前安装（属只读工具安装，不涉及第三方知识仓库）。
- **边界**：本决议仅授权此渲染验证；验证结果用于设计多机构模块，不改变已批准计划的数据合同；真实批量抓取、更大范围站点或性能压测仍需逐项另行授权。
