## 1. 目标

解决 R-48 暴露的「通用机构发现对地市官网覆盖不足」——部分地市（芜湖/淮北）机构列表 JS 动态渲染抽不到、部分（滁州/马鞍山）静态链接未被栏目正则覆盖。目标：

- **静态地市**：补齐部门栏目递归入口词（市直政府部门等），通用规则命中静态机构；
- **JS 动态地市**：机构发现支持浏览器升级（Playwright），渲染后抽机构；
- 不新增适配器，保持通用规则优先。

## 2. 现状差距（现场只读核验，真实站点证据）

| 地市 | 首页静态机构链接 | 栏目入口词 | 结论 |
|---|---|---|---|
| 滁州 chuzhou.gov.cn | **28 个**（局/委/办结尾） | 「市直政府部门」 | 静态可达，但「市直政府部门」不在递归正则 → 未命中 |
| 马鞍山 mas.gov.cn | **24 个** | — | 静态可达，但 selector 未覆盖其容器 |
| 蚌埠 bengbu.gov.cn | 0（首页无） | 无（部门列表 JS） | 但 Canary 曾从栏目递归抽出 3 机构 → 递归在某页命中 |
| 芜湖 wuhu.gov.cn | 0 | 无 | **全 JS 渲染** → 0 结果 |
| 淮北 huaibei.gov.cn | 0 | 无 | **全 JS 渲染** → 0 结果 |

**核心结论**：
1. **静态地市**（滁州/马鞍山等）：通用规则本身能抽，但 `discoverFromDepartmentColumns` 的栏目入口词（`政府机构|省政府办公厅|省直部门|直属单位|组成部门|机构设置|政府部门|省长之窗`）**不含「市直政府部门」等市级入口词** → 漏过；
2. **JS 动态地市**（芜湖/淮北）：`discoverInstitutions` 只做 HTTP 抓取，不消费 BrowserPool → JS 渲染的机构列表拿不到。

## 3. 设计决策（brainstorming 结论）

### 决策 D1：部门栏目递归入口词补充（静态地市）

- `discoverFromDepartmentColumns` 的栏目入口正则补充市级词：`市直部门|市直政府部门|部门网站|政府工作部门|市属机构|组织机构`；
- 通用 `extractCandidatesFromHtml` 的 selector 已含 `a.link`/`[class*='zfjg']` 等，滁州/马鞍山的机构容器若为标准列表即可命中（若为特殊容器，D2 覆盖）。

### 决策 D2：机构发现浏览器升级（JS 动态地市）

- `discoverInstitutions` 增可选 `browserPool?: BrowserPool`：
  - HTTP 抓取候选为空 且 有 browserPool → 渲染入口页 → 从渲染后 HTML 重跑抽取；
  - 渲染后仍空 → 如实空候选（调用方终态）；
- `multi-institution-driver` 传入已注入的 browserPool（R-46 已透传到驱动）；
- 边界：浏览器仅渲染授权 URL（入口页）；礼貌并发/资源限制沿用 P1。

### 决策 D3：边界

- 仅通用规则增强（栏目词 + 浏览器升级），**不新增适配器**；
- 地市无领导信息页仍如实「该机构无领导信息」（R-23 方向 2，地市官网普遍无领导页）；
- 不改数据合同/证据链/驱动核心语义；无新依赖；
- 真实验证仅限安徽 16 地市（R-45 授权延伸）。

## 4. 验收

- 静态地市（滁州/马鞍山）Canary：能抽到真实机构（≥3 个，不再 0/漏抽）；
- JS 动态地市（芜湖/淮北）Canary：浏览器升级后能抽到真实机构 或 如实空；
- 全量回归 typecheck/test/build 全绿。

## 5. 打开问题

1. **浏览器升级的时机**：仅当 HTTP 候选为空才渲染（避免每站都开浏览器）——建议此策略；
2. **渲染深度**：仅入口页渲染，还是栏目页也渲染——建议入口页渲染 + 栏目页 HTTP（先最小）；
3. **超时/资源**：浏览器渲染计入 P1 并发闸——建议沿用。
