# `crawler-enforce-security` 诊断记录输出契约

> 本文件定义本 Skill 的诊断记录契约、交接契约与修订保留。交接遵守主决策日志第 33 至 36 节的可落盘结构化记录、双层存储与敏感信息脱敏要求。

## 诊断记录输出契约

诊断记录采用可落盘结构化记录＋简短人类可读摘要（主决策日志第 33 节），每条结论可追溯。固定字段：

- 风险证据（定位到的代码/配置/URL/依赖/密钥处理位置）。
- 严重程度（高/中/低，按影响与可利用性评估）。
- 受影响范围（受影响的端点、功能面、数据、依赖链）。
- 允许/禁止结论（动作判定：允许 / 需要额外批准 / 明确禁止；明确禁止的给出合规替代）。
- 合规修复方向（可验证且不破坏边界，指向匹配版本资料）。
- 安全回归测试建议（静态扫描、隔离测试、漏洞复核）。
- 依据（关联证据卡 ID、固定资料路径、代码/配置/URL 位置）。

记录必须明确区分：事实、证据、推断、待确认项与用户批准状态。

## 交接契约

- 高风险问题或不合规方向**必须阻止进入普通修复流程**；只有获准的合规修复方向才交给 `crawler-writing-plans-bridge` 作为规划输入，不取代其规划职责。
- Docker 具体问题交给 `crawler-run-docker`；Node.js 运行时问题交给 `crawler-debug-typescript-node`；HTTP/网络问题交给 `crawler-debug-http-network`；PostgreSQL 问题交给 `crawler-use-postgresql`。
- 交接遵守主决策日志第 33-36 节：
  - 可落盘结构化记录＋简短人类可读摘要（第 33 节）；
  - 双层存储：小型结构化记录保存在项目内，大型证据以内容哈希和相对路径引用（第 35 节）；
  - 密钥、Cookie、认证请求头、代理凭据、环境变量中的秘密等敏感信息不得入记录，落盘前脱敏（第 36 节）。
- 处理 Stellaris 问题时，先读取 `stellaris-crawler-context` 生成的项目上下文包路径，诊断记录依据引用上下文包条目。

## 修订保留

- 每次诊断记录都是一个新修订，追加或通过修订记录指向被替代版本。
- 不得静默覆盖既有诊断记录；旧版本保持可读，用于审计。
- 修订记录只追加，指向被替代版本。

## 禁止

- 不建设安全扫描器、监控后端或爬虫运行组件。
- 不得提出绕过登录、验证码、访问权限或 WAF 的办法。
- 不得攻击外部网站（无授权渗透测试）。
- 不得把未经审查的第三方示例代码用于项目。
- 诊断默认只指导只读静态审查、配置审查和隔离环境安全测试；任何可能修改配置、环境变量、代码或运行中项目的动作须获得明确批准。
- 不绕过访问控制、不发起对目标站点的无授权请求。
- 不把外部条件或未知项伪装成已修复。
- 不生成 `writing-plans`、不提出未经批准的代码修改。
- 不修改爬虫代码、`manifest.md`、第三方仓库；不初始化 Git。
- 不把密钥、Cookie、认证请求头、代理凭据、环境变量中的秘密等敏感信息写入诊断记录。
