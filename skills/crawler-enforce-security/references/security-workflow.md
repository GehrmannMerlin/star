# `crawler-enforce-security` 诊断流程与动作判定规则

> 本文件定义本 Skill 的诊断流程、动作判定规则、问题分类规则与证据卡映射。判断依据与边界以主决策日志与已批准设计规格为准。

## 诊断流程

1. 读取项目上下文、目标、约束与已确认问题证据。处理 Stellaris 问题时，先读取 `stellaris-crawler-context` 生成的项目上下文包路径。
2. 确定诊断聚焦点（SSRF 与 URL/DNS 校验 / 重定向安全 / 密钥管理与凭据处理 / 依赖供应链 / 隔离执行与访问边界 / 证据展示与输出安全），聚焦该点，不做无边界全栈诊断。
3. 检查相关代码、配置、依赖清单、密钥处理方式、URL 使用、重定向逻辑、访问控制证据，定位具体证据位置。
4. 引用匹配版本的证据卡（`security-compliance.md`）比对项目行为与规范/实现/工程证据。
5. 判定动作属于**允许 / 需要额外批准 / 明确禁止**。
6. 分类：代码缺陷 / 配置错误 / 版本兼容 / 设计不足 / 外部条件 / 未知项。
7. 证据不足时只提出最小补充取证（静态扫描、配置审查、隔离环境安全测试）；根因未证实前不提出代码修改。
8. 输出可追溯风险证据、严重程度、受影响范围、允许/禁止结论、合规修复方向、安全回归测试建议。
9. 高风险问题或不合规方向必须阻止进入普通修复流程；获准的合规修复方向交给 `crawler-writing-plans-bridge`。

## 动作判定规则

- **允许**：合规且低风险的动作（只读审查、静态扫描、隔离环境安全测试）。
- **需要额外批准**：中等风险或修改性动作（修改配置/代码、执行隔离测试、访问受限资源）——须用户明确批准。
- **明确禁止**：
  - 绕过登录/验证码/访问权限/WAF；
  - 攻击外部网站（无授权渗透测试）；
  - SSRF 到私网/环回地址或利用 URL 缺陷访问内部服务；
  - 泄露密钥、Cookie、认证请求头、代理凭据、环境变量秘密；
  - 把未经审查的第三方示例代码用于项目；
  - 把外部条件或未知项伪装成已修复。
- 高风险问题或不合规方向必须阻止进入普通修复流程；明确禁止的动作给出合规替代方案。

## 问题分类规则

- **代码缺陷**：安全相关代码未按规范/实现证据处理（如 SSRF 防护缺失、重定向未校验目标、密钥硬编码）。
- **配置错误**：安全/合规配置与固定版本行为不符（如访问控制、代理、私网访问配置错误）。
- **版本兼容**：依赖版本与安全 API 行为不匹配（如存在已知漏洞的依赖版本）。
- **设计不足**：缺乏 URL 校验、密钥管理、隔离执行、访问边界等设计层面缺失。
- **外部条件**：外部网站访问受限、访问控制限制等——只能给合规降级/等待/终止结论，不得伪装成已修复（主决策日志 §12/§57）。
- **未知项**：证据不足或冲突，保持候选假设，显式标记，不判定为确定根因。

每条结论必须明确区分：事实、证据、综合推断、待确认项。综合推断必须显式标记为"推断"，不得伪装成资料中的确定结论（主决策日志 §14）。

置信度使用固定枚举：高（证据充分且指向唯一分类）、中（证据充分但多个分类可能）、低（证据不足或冲突，仅候选假设）、不确定（无法判断）。

## 只读诊断边界

- 诊断默认只指导只读静态审查、配置审查和隔离环境安全测试。
- 任何可能修改配置、环境变量、代码或运行中项目的动作须获得明确批准。
- 不执行攻击性测试、不发起对目标站点的无授权请求、不绕过访问控制。
- 诊断复现限受控、合规；不得发起新的对外抓取或绕过访问控制。

## 证据不足与冲突

- 证据不足时不得把结论判定为确定根因；保留候选状态并标记未知项。
- 现场证据、项目上下文、已批准要求冲突时并列报告，不静默覆盖任一来源。
- 未解决的声明标记为不确定（非确定性），不得伪装成确定结论。
- 固定版本证据卡与既有诊断记录不得被静默改写；更新只通过新增修订进行。
- 外部条件（外部网站访问受限/访问控制限制）只能给合规降级/等待/终止结论，不得伪装成已修复。
- 安全漏洞必须暴露，不得用默认值或猜测掩盖，不得把风险伪装成已修复。
- 不得因新技术更新默认要求升级；是否升级以证据和项目约束为准。
