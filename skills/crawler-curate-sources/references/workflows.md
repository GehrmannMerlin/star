# `crawler-curate-sources` 工作流

> 三种模式的有序流程、输入、审查步骤、停止条件与输出。判断依据引用共享证据层证据卡与 `crawler-curate-sources` 知识视图。

## 通用审查序列

每次来源审查都按固定顺序执行：

1. 相关性：来源是否直接服务于目标 Skill 或知识缺口。
2. **权威来源**：核验 canonical 上游与官方性，不以镜像或二手来源为准。
3. **维护状态**：观察仓库活跃度、归档状态与维护节奏。
4. **许可证**：核验许可证证据，识别缺失或冲突。
5. **适用版本**：确定来源适用的版本范围，不与项目锁定版本脱节。
6. canonical 上游：确认权威 origin 与镜像关系。
7. 去重：与既有 accepted／candidate／rejected 记录比对。
8. **预计体积**：估算浅克隆体积与对第三方资料库容量、E 盘可用空间的影响。
9. 分类：归入 accepted／candidate／rejected。

## 模式一：首次资料基线

**输入：** 目标 Skill 或知识缺口、预期版本范围、当前 `manifest.md`、用户批准约束、E 盘可用空间、既有分类记录（通常为空）。

**流程：**
1. 加载知识视图与证据卡，读取主决策日志与统一规格。
2. 第一遍：只联网发现与审查候选来源，执行通用审查序列，不下载源码。
3. 形成准入清单、候选清单和拒绝清单，交用户核对。
4. 等待用户批准，任何来源不得提前克隆。

**停止条件：** 用户批准前停止在第一遍；容量、许可证、权威来源或安全边界失败时单独停止对应来源。

**输出：** 三份分离清单及合计、预计容量、待批准项。

## 模式二：按需增量更新

**输入：** 目标 Skill、当前 `manifest.md`、既有 accepted／candidate／rejected 记录、项目依赖版本变化或故障资料不足的信号、E 盘可用空间。

**流程：**
1. 读取既有清单与记录，识别应检查的来源集合。
2. 对候选来源执行通用审查序列；对既有获准来源核验 ref 与 Commit 是否仍匹配。
3. 第一遍形成新增／更新建议清单，交用户批准。
4. 用户批准后进入第二遍，固定 ref 与 **固定 Commit**，执行 **浅克隆** 到 E 盘。

**停止条件：** 用户批准前不下载；ref 或 Commit 变更在未批准前只记录为新候选；容量或安全边界触发时停止。

**输出：** 更新的三份清单、新增或更新的快照记录、容量变化与停止报告（如适用）。

## 模式三：定向补充

**输入：** 已命名知识缺口、目标 Skill、当前 `manifest.md`、既有记录、E 盘可用空间。

**流程：**
1. 明确缺口名称与直接相关性范围，不与全库扩展混淆。
2. 只对与缺口直接相关的来源执行通用审查序列。
3. 第一遍形成新增建议清单，交用户批准。
4. 用户批准后固定 ref 与 Commit、浅克隆到 E 盘。

**停止条件：** 只补充缺口相关来源；与缺口无关来源不得纳入；容量或安全边界触发时停止。

**输出：** 缺口对应新增清单、快照记录、缺口映射说明。

## 第二遍（获准后）共同流程

1. 核验用户批准状态与授权范围。
2. 检查 E 盘可用空间与第三方资料库累计容量（50 GB 软上限、120 GB 可用空间）。
3. 固定 canonical 上游、ref、40 位 Commit 与许可证证据。
4. 执行浅克隆到 E 盘资料区，记录本地相对路径。
5. 复核：浅克隆状态、origin 与权威上游一致、工作区洁净、许可证证据存在。
6. 记录实际字节与采集时间。

**失败处理：** 单个仓库失败时停止该仓库，不替换为候选或拒绝仓库，也不阻塞其他已批准仓库，除非触发全局容量或安全边界。

## 停止条件汇总

- 用户批准门：第一遍输出清单后必须等待批准。
- 许可证缺失或不可核实：拒绝下载，保留元数据。
- canonical 上游不明确：不自动选择，请求用户确认。
- 容量边界：50 GB 软上限或 E 盘可用空间低于 120 GB 时停止新增下载。
- 安全边界：任何第三方程序执行请求都被拒绝。
