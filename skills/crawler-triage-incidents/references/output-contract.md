# `crawler-triage-incidents` 分诊结论输出契约

> 本文件定义本 Skill 的分诊结论记录契约、交接契约与修订保留。交接遵守主决策日志第 33 至 36 节的可落盘结构化记录、双层存储与敏感信息脱敏要求。

## 分诊结论输出契约

分诊结论采用可落盘结构化记录＋简短人类可读摘要，每条结论可追溯（从记录追到证据位置或上下文包条目）。固定字段：

- 分诊结论（问题层次分类：内部缺陷/外部限制/未知问题）。
- 证据缺口（已满足/缺失的最小证据）。
- 路由目标（应调用的领域 Skill 与重点技术栈 Skill）。
- 置信程度（高/中/低/不确定）。
- 依据（引用故障现象、证据位置、上下文包条目）。
- 交接对象（下游领域/技术栈 Skill 或用户）。

记录必须明确区分：事实、证据、推断、待确认项与用户批准状态。

## 交接契约

- 分诊结论交接给下游领域 Skill 或技术栈 Skill 作为诊断输入，不取代其完整诊断。
- 交接遵守主决策日志第 33-36 节：
  - 可落盘结构化记录＋简短人类可读摘要（第 33 节）；
  - 双层存储：小型结构化记录保存在项目内，大型证据以内容哈希和相对路径引用（第 35 节）；
  - 密钥、Cookie、认证请求头等敏感信息不得入记录，落盘前脱敏（第 36 节）。
- 处理 Stellaris 问题时，先读取 `stellaris-crawler-context` 生成的项目上下文包路径，分诊结论引用上下文包条目作为依据。

## 修订保留

- 每次分诊记录都是一个新修订，追加或通过修订记录指向被替代版本。
- 不得静默覆盖既有分诊记录；旧版本保持可读，用于审计。
- 修订记录只追加，指向被替代版本。

## 禁止

- 不深入解决领域问题、不提出代码修改、不生成 Superpowers `writing-plans`。
- 不把外部限制、未知问题或证据不足误判为已定位根因。
- 不把未确认猜测当作确定结论；不静默消解证据冲突。
- 不把密钥、Cookie、认证头等敏感信息写入分诊记录。
- 不建设运行服务、RAG、代码索引、上下文框架。
- 不修改爬虫代码、`manifest.md`、第三方仓库；不初始化 Git。
