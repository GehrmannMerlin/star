# `crawler-automate-browsers` 诊断记录输出契约

> 本文件定义本 Skill 的诊断记录契约、交接契约与修订保留。交接遵守主决策日志第 33 至 36 节的可落盘结构化记录、双层存储与敏感信息脱敏要求。

## 诊断记录输出契约

诊断记录采用可落盘结构化记录＋简短人类可读摘要（主决策日志第 33 节），每条结论可追溯。固定字段：

- 问题证据（定位到的代码/配置/日志/Trace/DOM/截图/网络记录位置）。
- 分类（代码缺陷 / 配置错误 / 版本兼容 / 页面行为变化 / 外部限制 / 未知项；含置信度：高/中/低/不确定）。
- 根因或待验证假设（区分事实、证据、推断、待确认项）。
- 影响范围（受影响的页面、元素、数据、资源）。
- 修复方向（可验证且合规的修复建议，指向匹配版本资料）。
- 浏览器层测试建议（能稳定暴露问题的失败案例思路）。
- 交接对象（根因和方向获批后 → `crawler-writing-plans-bridge`）。

记录必须明确区分：事实、证据、推断、待确认项与用户批准状态。

## 交接契约

- 根因和方向获批后，诊断结论交接给 `crawler-writing-plans-bridge` 作为规划输入，不取代其规划职责。
- 交接遵守主决策日志第 33-36 节：
  - 可落盘结构化记录＋简短人类可读摘要（第 33 节）；
  - 双层存储：小型结构化记录保存在项目内，大型证据以内容哈希和相对路径引用（第 35 节）；
  - 密钥、Cookie、认证请求头等敏感信息（含截图内容）不得入记录，落盘前脱敏（第 36 节）。
- 处理 Stellaris 问题时，先读取 `stellaris-crawler-context` 生成的项目上下文包路径，诊断记录依据引用上下文包条目。

## 修订保留

- 每次诊断记录都是一个新修订，追加或通过修订记录指向被替代版本。
- 不得静默覆盖既有诊断记录；旧版本保持可读，用于审计。
- 修订记录只追加，指向被替代版本。

## 禁止

- 不承担项目的生产页面抓取和渲染。
- 不默认使用固定长等待或把 `networkidle` 当作通用完成条件。
- 不绕过登录、验证码、访问控制或 WAF。
- 不执行过度浏览器复现或无效轰击；诊断复现限小规模、隔离、合规。
- 不把外部限制或未知项伪装成已修复。
- 不生成 `writing-plans`、不提出未经批准的代码修改。
- 不修改爬虫代码、`manifest.md`、第三方仓库；不初始化 Git。
- 不把密钥、Cookie、认证请求头等敏感信息（含截图内容）写入诊断记录。
