# `crawler-validate-extraction` 诊断流程与分类规则

> 本文件定义本 Skill 的诊断流程、问题分类规则与证据卡映射。判断依据与边界以主决策日志与已批准设计规格为准。

## 诊断流程

1. 读取项目上下文、目标、约束与已确认问题证据。处理 Stellaris 问题时，先读取 `stellaris-crawler-context` 生成的项目上下文包路径。
2. 确定诊断聚焦点（HTML/DOM 解析 / JSON·结构化数据 / 文本编码 / Selector·字段映射 / 数据校验·数据质量），聚焦该点，不做无边界全栈诊断。
3. 检查相关代码、配置、依赖版本、原始页面证据、抽取结果、金标预期，定位具体证据位置。
4. 引用匹配版本的证据卡（`extraction-quality.md`）比对项目行为与规范/实现/工程证据。
5. 分类：代码缺陷 / 配置错误 / 版本兼容 / 页面行为变化 / 外部条件 / 未知项。
6. 证据不足时只提出最小补充取证或离线回放；根因未证实前不提出代码修改。
7. 输出可追溯问题证据、根因或待验证假设、影响范围、修复方向、回归样例。
8. 根因和方向获批后，将选定方向交给 `crawler-writing-plans-bridge`。

## 问题分类规则

- **代码缺陷**：解析/抽取代码未按规范/实现证据处理（如 Selector 错误、字段映射错位、编码处理缺失）。
- **配置错误**：解析配置/参数与固定版本行为不符（如编码声明、解析器设置错误）。
- **版本兼容**：依赖版本与 API 行为不匹配（如 jsoup/readability 版本差异导致解析行为变化）。
- **页面行为变化**：目标站点 DOM/结构/JSON 结构变化导致字段错位、Select 失效——需重新取证而非盲改代码。
- **外部条件**：目标站点拒绝、访问限制、页面结构特殊等——只能给合规降级/等待/终止结论，不得伪装成已修复（主决策日志 §12/§53）。
- **未知项**：证据不足或冲突，保持候选假设，显式标记，不判定为确定根因。

每条结论必须明确区分：事实、证据、综合推断、待确认项。综合推断必须显式标记为"推断"，不得伪装成资料中的确定结论（主决策日志 §14）。

置信度使用固定枚举：高（证据充分且指向唯一分类）、中（证据充分但多个分类可能）、低（证据不足或冲突，仅候选假设）、不确定（无法判断）。

## 隐蔽数据错误重点

- 特别识别"程序成功但数据错误"的隐蔽问题：程序不报错但字段缺失、错位、乱码、过期、冲突。
- 检测方法：结合金标预期比对抽取结果，使用已保存证据执行小规模离线回放。
- 禁止用默认值或猜测掩盖字段缺失与冲突；必须暴露真实数据问题，供用户批准修复方向。

## 证据卡映射

共享证据卡：`docs/superpowers/knowledge/evidence-cards/extraction-quality.md`；知识视图：`docs/superpowers/knowledge/skill-views/crawler-validate-extraction.md`。

| 诊断聚焦点 | 证据卡 | 固定资料路径 |
|---|---|---|
| HTML/DOM 解析 | VE-HTML-001、VE-HTML-002、VE-HTML-003 | jsoup `org/jsoup/parser`、`org/jsoup/nodes`；readability `Readability.js`、`JSDOMParser.js` |
| JSON/结构化数据 | VE-JSON-001、VE-JSON-002、VE-JSON-003 | readability `Readability.js`（JSON.parse、_getArticleMetadata）；whatwg/url `url.bs` |
| 文本编码 | VE-ENC-001、VE-ENC-002 | jsoup `helper/DataUtil.java`；whatwg/url `url.bs` |
| Selector/字段映射 | VE-SEL-001、VE-SEL-002、VE-SEL-003 | jsoup `org/jsoup/select/Evaluator.java`、`Collector.java`；readability `Readability.js` |
| 数据校验/数据质量 | VE-VAL-001、VE-VAL-002 | jsoup `org/jsoup/safety`；readability `Readability-readerable.js` |

每条依据必须可追溯：从诊断记录追到固定版本资料、证据卡、上下文包条目或决策日志节号。只给仓库首页、模糊文件夹或没有版本的引用不满足要求。

## 离线回放边界

- 诊断确有必要时，可以指导 Agent 使用已保存证据（原始页面证据/抽取结果）执行小规模离线回放用于验证假设。
- 回放不得承担项目的生产解析功能；不负责联网抓取或浏览器渲染。
- 回放必须使用已保存证据，不得发起新的对外请求或绕过访问控制。

## 证据不足与冲突

- 证据不足时不得把结论判定为确定根因；保留候选状态并标记未知项。
- 现场证据、项目上下文、已批准要求冲突时并列报告，不静默覆盖任一来源。
- 未解决的声明标记为不确定（非确定性），不得伪装成确定结论。
- 固定版本证据卡与既有诊断记录不得被静默改写；更新只通过新增修订进行。
- 外部条件（站点拒绝/访问限制/结构特殊）只能给合规降级/等待/终止结论，不得伪装成已修复。
- 隐蔽数据错误必须暴露，不得用默认值或猜测掩盖。
- 不得因新技术更新默认要求升级；是否升级以证据和项目约束为准。
