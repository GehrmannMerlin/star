# `crawler-test-regressions` 诊断流程与测试设计规则

> 本文件定义本 Skill 的诊断流程、测试设计规则、外部条件分离与发布阻断规则、证据卡映射。判断依据与边界以主决策日志与已批准设计规格为准。

## 诊断流程

1. 读取项目上下文、目标、约束与已确认根因。处理 Stellaris 问题时，先读取 `stellaris-crawler-context` 生成的项目上下文包路径。
2. 确定诊断聚焦点（单元/集成测试设计 / 回放测试与金标数据 / 契约测试 / 故障注入与性能测试 / 安全回归 / 修复验证与发布阻断），聚焦该点，不做无边界全栈诊断。
3. 检查相关代码、测试体系、依赖版本、验收标准、复现证据，定位具体证据位置。
4. 引用匹配版本的证据卡（`test-regressions.md`）比对项目行为与规范/实现/工程证据。
5. 修复前：设计能够稳定暴露问题的失败案例（RED）；用户批准实施后指导运行并保存结果证据（GREEN）。
6. 检查修复是否真正解决原问题、是否引入新问题、外部网站异常是否被错误计入项目自身测试失败。
7. 测试发现新的未知问题时，必须退回 `crawler-triage-incidents`。
8. 输出测试范围、测试依据、通过或失败结果、未覆盖风险和发布阻断结论。
9. 安全或正确性硬门槛失败时，必须阻止通过（发布阻断）；获准的修复方向交给 `crawler-writing-plans-bridge`。

## 测试设计规则

- 先写能稳定暴露问题的失败案例，再写修复（RED-GREEN 纪律）。
- 修复前：形成稳定失败案例（RED），运行确认失败。
- 修复获批实施后：运行测试并保存结果证据（GREEN）。
- 测试必须可复现、有结果证据；无结果证据时不宣称修复成功。
- 外部网站异常与项目自身缺陷必须分离，不得把外部条件误计入项目测试失败。
- 金标数据与回放测试基于已保存证据，不依赖实时抓取。

每条结论必须明确区分：事实、证据、综合推断、待确认项。综合推断必须显式标记为"推断"，不得伪装成资料中的确定结论（主决策日志 §14）。

置信度使用固定枚举：高（证据充分且指向唯一分类）、中（证据充分但多个分类可能）、低（证据不足或冲突，仅候选假设）、不确定（无法判断）。

## 外部条件分离与发布阻断

- **外部条件分离**：外部网站异常（超时/503/不可用）与项目自身缺陷必须分离；外部条件只能给合规降级/等待/终止结论，不得把外部网站异常误计入项目自身测试失败，不得伪装成已修复（主决策日志 §12/§58）。
- **发布阻断**：安全或正确性硬门槛测试失败时，必须阻止通过（发布阻断）；关键回归失败时不得放行；无结果证据时不得宣称修复成功。
- **toxiproxy 边界**：按主决策日志 §70，toxiproxy 只作受控网络退化案例的知识来源；不授权启动代理、影响现有环境或注入故障。

## 只读诊断边界

- 诊断默认只指导只读静态审查、配置审查和测试设计。
- 任何测试运行、故障注入、启动代理或修改动作须获得明确批准。
- 不攻击外部网站、不绕过访问控制、不发起对目标站点的无授权请求。
- 诊断复现限受控、合规；不得发起新的对外抓取或绕过访问控制。
- toxiproxy 按主决策日志 §70：不授权启动代理、影响现有环境或注入故障。

## 证据不足与冲突

- 证据不足时不得把结论判定为确定根因；保留候选状态并标记未知项。
- 现场证据、项目上下文、已批准要求冲突时并列报告，不静默覆盖任一来源。
- 未解决的声明标记为不确定（非确定性），不得伪装成确定结论。
- 固定版本证据卡与既有诊断记录不得被静默改写；更新只通过新增修订进行。
- 无结果证据时不宣称修复成功；关键回归失败时不放行。
- 外部网站异常必须与项目自身缺陷分离，不得伪装成已修复。
- 不得因新技术更新默认要求升级；是否升级以证据和项目约束为准。
