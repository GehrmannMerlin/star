# `crawler-review-architecture` 评审流程与比较规则

> 本文件定义本 Skill 的评审流程、六维方案比较规则与迁移风险评估。判断依据与边界以主决策日志与已批准设计规格为准。

## 评审流程

1. 读取项目上下文、目标、约束与已确认问题证据。
2. 明确本次评审的触发层次（架构/数据模型/业务规则/技术路线/验收标准之一），聚焦该层，不做无边界全栈评审。
3. 确定"保持现状"作为基线方案。
4. 提出 1-3 个可行替代方案（含理由），分别说明：资料依据、适用条件、收益、代价、影响范围、迁移风险。
5. 公平比较各方案，输出推荐方向＋保留备选＋未知项。
6. 向用户呈现评审报告，等待用户明确批准。
7. 用户批准后，将选定方向交给 `crawler-writing-plans-bridge`。

处理 Stellaris 问题时，先读取 `stellaris-crawler-context` 生成的项目上下文包路径，再执行上述评审流程；评审报告依据引用上下文包条目。

## 方案比较规则

比较维度固定：

- 证据依据（引用固定版本资料、证据卡、上下文包条目、决策日志节号）。
- 适用条件（方案成立的前提与边界）。
- 收益（带来的改进或价值）。
- 代价（实施成本、维护成本、取舍）。
- 影响范围（受影响的组件、数据、测试、部署）。
- 迁移风险（破坏风险、回滚难度、实施工作量）。

每条依据必须可追溯：从评审报告追到固定版本资料、证据卡、上下文包条目或决策日志节号。只给仓库首页、模糊文件夹或没有版本的引用不满足要求。

明确区分：事实、证据、推断、未知项。综合推断必须显式标记为"推断"，不得伪装成资料中的确定结论。

## 迁移风险评估

- 对每个替代方案，说明影响范围（受影响的组件、数据、测试、部署）与迁移风险（破坏、回滚、工作量）。
- 在适用时保留"保持现状"作为低风险基线选项。
- 迁移风险评估基于项目锁定版本与项目约束，不基于"最新更好"的预设。

## 证据不足与冲突

- 证据不足时不得把结论判定为确定方向；保留候选状态并标记未知项。
- 现场证据、项目上下文、已批准要求冲突时并列报告，不静默覆盖任一来源。
- 未解决的声明标记为不确定（非确定性），不得伪装成确定结论。
- 固定版本证据卡与既有评审报告不得被静默改写；更新只通过新增修订进行。
- 不得因新技术更新默认要求升级；是否升级以证据和项目约束为准。
