# `crawler-use-playwright` 诊断记录输出契约

> 本文件定义本 Skill 的诊断记录契约、交接契约与修订保留。交接遵守主决策日志第 33 至 36 节的可落盘结构化记录、双层存储与敏感信息脱敏要求。

## 诊断记录输出契约

诊断记录采用可落盘结构化记录＋简短人类可读摘要（主决策日志第 33 节），每条结论可追溯。固定字段：

- 问题证据（定位到的 Playwright 代码/配置/依赖版本/Trace/截图/日志/复现证据位置）。
- 分类（代码缺陷 / 配置错误 / 版本兼容 / 设计不足 / 外部条件 / 未知项；含置信度：高/中/低/不确定）。
- 根因或待验证假设（区分事实、证据、推断、待确认项）。
- 影响范围（受影响的 Browser、Context、Page、Locator、网络请求链）。
- 修复方向（适合当前 Playwright 版本的具体实现建议，指向匹配版本资料）。
- 测试建议（隔离的最小复现、Trace 分析、回归测试方法）。
- 依据（关联证据卡 ID、固定资料路径、代码/配置/日志位置）。

记录必须明确区分：事实、证据、推断、待确认项与用户批准状态。

## 交接契约

- 将 `crawler-automate-browsers` 已确认方向转换为 Playwright 实现建议，但不得越过用户批准边界或跳过 `crawler-writing-plans-bridge`。
- 获准的修复方向交给 `crawler-writing-plans-bridge` 作为规划输入，不取代其规划职责。
- Docker 具体问题交给 `crawler-run-docker`。
- 交接遵守主决策日志第 33-36 节：
  - 可落盘结构化记录＋简短人类可读摘要（第 33 节）；
  - 双层存储：小型结构化记录保存在项目内，大型证据（Trace、截图、视频）以内容哈希和相对路径引用（第 35 节）；
  - 密钥、Cookie、认证请求头、代理凭据、环境变量中的秘密等敏感信息不得入记录，落盘前脱敏（第 36 节）。
- 处理 Stellaris 问题时，先读取 `stellaris-crawler-context` 生成的项目上下文包路径，诊断记录依据引用上下文包条目。

## 修订保留

- 每次诊断记录都是一个新修订，追加或通过修订记录指向被替代版本。
- 不得静默覆盖既有诊断记录；旧版本保持可读，用于审计。
- 修订记录只追加，指向被替代版本。

## 禁止

- 不承担生产页面抓取。
- 不得提供绕过登录、验证码、访问控制或 WAF 的方法。
- 不把"适用版本准确"误判为"运行行为正确"；等待竞态、定位不稳定、上下文泄漏需运行时证据判定。
- 不引用不存在或已经变更的 API（版本差异）。
- 不越过用户批准边界、不跳过 `crawler-writing-plans-bridge`。
- 不安装、构建或运行未经批准的项目或第三方代码。
- 不攻击外部网站、不绕过访问控制、不发起对目标站点的无授权请求。
- 不把未经审查的第三方示例代码用于项目。
- 不生成 `writing-plans`、不提出未经批准的代码修改。
- 不修改爬虫代码、`manifest.md`、第三方仓库；不初始化 Git。
- 不把密钥、Cookie、认证请求头、代理凭据、环境变量中的秘密等敏感信息写入诊断记录。
