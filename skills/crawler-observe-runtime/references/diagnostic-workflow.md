# `crawler-observe-runtime` 诊断流程与分类规则

> 本文件定义本 Skill 的诊断流程、问题分类规则与证据卡映射。判断依据与边界以主决策日志与已批准设计规格为准。

## 诊断流程

1. 读取项目上下文、目标、约束与已确认问题证据。处理 Stellaris 问题时，先读取 `stellaris-crawler-context` 生成的项目上下文包路径。
2. 确定诊断聚焦点（运行环境 / 环境变量 / 资源限制 / 健康检查 / 日志 / 指标 / Trace / 故障现场完整性），聚焦该点，不做无边界全栈诊断。
3. 检查相关配置、运行状态、日志、指标、Trace 和资源证据，定位具体证据位置。
4. 引用匹配版本的证据卡（`runtime-observability.md`）比对项目行为与规范/实现/工程证据。
5. 分类：代码缺陷 / 配置错误 / 版本兼容 / 设计不足 / 外部条件 / 未知项。
6. 证据不足时只提出最小补充取证（只读环境检查、短时诊断、日志/指标/Trace 采集要求）；根因未证实前不提出代码修改。
7. 输出可追溯运行现象、证据缺口、影响范围、观测盲区、问题分类与置信度、建议加载的领域/技术栈 Skill。
8. 根因和方向获批后，将选定方向交给 `crawler-writing-plans-bridge`。

## 问题分类规则

- **代码缺陷**：运行/观测相关代码未按规范/实现证据处理（如健康检查判定错误、日志/指标/Trace 采集代码错误）。
- **配置错误**：运行/观测配置与固定版本行为不符（如环境变量、资源限制、采集端点、采样率配置错误）。
- **版本兼容**：运行时/观测依赖版本与 API 行为不匹配。
- **设计不足**：缺乏日志/指标/Trace 采集、健康检查、运行现场证据等设计层面缺失。
- **外部条件**：运行环境不可用、资源环境受限等——只能给合规降级/等待/终止结论，不得伪装成已修复（主决策日志 §12/§56）。
- **未知项**：证据不足或冲突，保持候选假设，显式标记，不判定为确定根因。

每条结论必须明确区分：事实、证据、综合推断、待确认项。综合推断必须显式标记为"推断"，不得伪装成资料中的确定结论（主决策日志 §14）。

置信度使用固定枚举：高（证据充分且指向唯一分类）、中（证据充分但多个分类可能）、低（证据不足或冲突，仅候选假设）、不确定（无法判断）。

## 观测与根因边界

- 本 Skill 只确凿说明"发生了什么、在哪里发生"：运行现象、证据缺口、影响范围、观测盲区。
- 不以观测现象代替业务根因，不把表面症状直接报告为根因；业务根因由相应领域 Skill 判定。
- 例如：内存耗尽/OOM 是运行现象，业务根因（如代码内存泄漏）须由相应领域/技术栈 Skill 结合项目证据确认，本 Skill 不得仅凭现象断言。
- 输出必须区分观测事实与推断，并列出建议加载的领域/技术栈 Skill。

## 只读诊断边界

- 诊断默认只指导只读环境检查和短时诊断（读取配置、环境变量、运行状态、日志尾部、健康检查响应、指标端点）。
- 任何可能修改配置、环境变量、代码或运行中项目的动作须获得明确批准。
- 不执行破坏性诊断（不杀进程、不修改资源限制、不重启动态环境）。
- 诊断复现限受控、合规；不得发起新的对外抓取或绕过访问控制。
- 不常驻监控、不替代项目运行系统。

## 证据不足与冲突

- 证据不足时不得把结论判定为确定根因；保留候选状态并标记未知项。
- 现场证据、项目上下文、已批准要求冲突时并列报告，不静默覆盖任一来源。
- 未解决的声明标记为不确定（非确定性），不得伪装成确定结论。
- 固定版本证据卡与既有诊断记录不得被静默改写；更新只通过新增修订进行。
- 外部条件（运行环境不可用/资源环境受限）只能给合规降级/等待/终止结论，不得伪装成已修复。
- 观测缺口必须暴露，不得用默认值或猜测掩盖，不得把观测现象直接报告为业务根因。
- 不得因新技术更新默认要求升级；是否升级以证据和项目约束为准。
