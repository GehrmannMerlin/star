# `stellaris-crawler-context` 动态核验与字段契约

> 本文件定义本 Skill 的现场只读核验流程、五类内容×固定字段契约与项目上下文包模板。判断依据与边界以主决策日志与已批准设计规格为准；上下文包产物落盘到 `docs/superpowers/knowledge/context-packages/`。

## 动态核验流程

每次处理按以下顺序执行（全部只读，不运行项目、不安装、不构建、不启动服务、不修改任何文件）：

1. **读取固定必读**：主决策日志 → 统一知识设计规格 → 第 6 批资料审查。动态提取已批准要求（`docs/superpowers/brainstorming/2026-07-31-crawler-knowledge-skills-decision-log.md` 中明确记录为已确认的内容），不另建独立批准清单。
2. **现场只读核验当前项目事实**：
   - 目录结构；
   - 依赖及锁文件（`package.json`、`package-lock.json`、`pnpm-lock.yaml`、`yarn.lock` 等）是否存在；
   - 配置（`tsconfig.json`、Dockerfile、Compose 文件等）是否存在；
   - 测试、启动与验证命令是否存在；
   - E 盘可用空间与第三方资料库累计容量（50 GB 软上限、120 GB 可用空间底线）；
   - 确认 `.superpowers/brainstorm/**` 工具依赖与 `third-party/crawler-knowledge-sources/repos/**` 快照**不属于**项目实现事实。
3. **识别冲突**：现场事实 vs 批准要求 vs 历史草案（如主决策日志第 72 节状态差异、第 75 节版本基线）。冲突并列报告，不自行选择其一。
4. **按五类×固定字段组织输出**。
5. **追加落盘**到 `docs/superpowers/knowledge/context-packages/`，保留修订，不静默覆盖。

## 五类内容×固定字段契约

| 内容类别 | 固定字段 |
|---|---|
| 当前代码事实 | 标签（current fact）、值/内容、来源位置（可核验路径）、验证时间、证据等级 |
| 已批准要求 | 标签（approved requirement）、值/内容、来源位置（主决策日志节号）、批准状态 |
| 历史设计草案 | 标签（historical draft）、值/内容、来源位置（2026-07-30 文档节号）、不得覆盖硬约束声明 |
| 冲突与未知项 | 标签（conflict/unknown）、冲突双方或未知描述、相关来源位置、状态（保持可见/不确定） |
| 建议分诊重点 | 标签（triage focus）、建议领域、依据（引用上文条目）、非根因结论声明 |

每条结论必须可追溯：从上下文包追到来源位置，再追到现场文件或主决策日志章节。只给出仓库首页、模糊目录或没有版本的引用不满足要求。

## 上下文包模板

```markdown
# <主题> 项目上下文包
> 生成时间 / 现场核验时间 / 生成角色
## 1. 当前代码事实
## 2. 已批准要求
## 3. 历史设计草案
## 4. 冲突与未知项
## 5. 建议分诊重点
## 6. 修订记录（只追加，指向被替代版本）
```

文件名：`YYYY-MM-DD-<主题>-context-package.md`。

## 证据不足与冲突

- 证据不足时不得把结论判定为确定事实；保留候选状态并标记未知项。
- 现场事实、批准要求、历史草案冲突时并列报告，不静默覆盖任一来源。
- 未解决的声明标记为不确定（非确定性），不得伪装成确定结论。
- 固定版本证据卡与既有上下文包修订不得被静默改写；更新只通过新增修订进行。
- 历史草案不得覆盖主决策日志或固定清单，冲突保持可见。
- Scorecard、Stars、许可证检测器、收割元数据、案例各保留其证据角色，不互相替换。
